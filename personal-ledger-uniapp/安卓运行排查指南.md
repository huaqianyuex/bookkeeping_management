# UniApp 安卓真机运行排查指南

## 问题现象

### 问题 A：应用无法启动
在 HBuilderX 中运行到安卓真机时，手机显示：
> **"本应用无法独立运行，需与 HBuilderX 搭配使用"**

### 问题 B：网络请求失败 + AI 创建会话失败
控制台报错：
```
request:fail abort statusCode:-1 Failed to connect to /192.168.101.84:8080
创建会话失败
id error: scroll-into-view=msg-{{currentMsgId}}
```

---

## 根本原因分析（问题 A）

这是 **uni-app 3.0 (Vue3 + Vite)** 项目在 App 端运行的典型问题，主要由以下原因导致：

1. **HBuilderX 版本过低** — Vue3 的 App 端需要 HBuilderX ≥ 3.6.0
2. **未使用自定义基座** — Vue3 项目必须用自定义基座运行
3. **缺少 App 端依赖** — 缺少 `@dcloudio/uni-app-plus`

## 根本原因分析（问题 B）

经过排查，你的环境确认：

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 后端服务 | ✅ 运行中 | 端口 8080 在监听 (`0.0.0.0:8080`) |
| 局域网 IP | ✅ 正确 | 手机 IP: `192.168.101.95`，电脑 IP: `192.168.101.84` |
| 已有连接 | ✅ 正常 | 手机与后端已有 ESTABLISHED 连接 |

所以**网络本身是通的**！请求失败的原因有多个：

### 原因 1（已修复）：API 路径错误 ⚠️ **核心 Bug**

前端 AI 接口调用路径与后端不匹配：

| 接口 | 前端原调用（❌ 错误） | 后端实际路径（✅ 正确） |
|------|---------------------|----------------------|
| 创建会话 | `/api/sessions` | `/api/ai/sessions` |
| 会话列表 | `/api/sessions` | `/api/ai/sessions` |
| 发送消息 | `/api/chat` | `/api/ai/chat` |

后端 `AiController.java` 的类级别注解是 `@RequestMapping("/api/ai")`，所以所有 AI 接口都需要 `/ai` 前缀。前端遗漏了这个前缀。

### 原因 2（已修复）：App 前后台切换导致请求中断
- 日志显示：`App Show` → `App Hide` → `请求失败`，间隔不到 20ms
- 应用启动时的页面跳转/生命周期切换会自动取消正在进行的请求

### 原因 3（已修复）：AI 聊天页面进入时自动创建会话
- 原代码在 `onLoad()` 时就调用 `createSession()`
- 如果此时 App 还没完全初始化好，请求就会被中断
- 用户看到的 "创建会话失败" 就是这个原因

### 原因 4（已修复）：scroll-into-view 模板语法错误
- 原代码：`scroll-into-view="msg-{{currentMsgId}}"`（静态字符串）
- 应为：`:scroll-into-view="'msg-' + currentMsgId"`（动态绑定）

### 原因 5（需用户操作）：登录状态

如果手机浏览器直接访问 `http://192.168.101.84:8080/api/sessions` 返回 401，这是**正常的**——因为浏览器没有携带登录 Token。

在 App 中使用时需要：
1. 先通过**登录页**完成登录（Token 会存储到本地）
2. 后续所有 API 请求会自动携带 Token
3. 如果仍然 401 → 可能 Token 过期或未正确保存

## 你需要手动完成的步骤（问题 A 修复）

### 步骤一：确认 HBuilderX 版本

打开 HBuilderX，点击菜单 **帮助 > 关于**，确认版本号 >= **3.6.0**。

如果版本过低，请前往 [DCloud 官网](https://www.dcloud.io/hbuilderx.html) 下载最新版。

### 步骤二：安装依赖

在项目的 `personal-ledger-uniapp` 目录下执行：

```bash
npm install
```

或：

```bash
pnpm install
```

这会安装新增的 `@dcloudio/uni-app-plus` 依赖。

### 步骤三：制作自定义基座

1. 在 HBuilderX 中打开本项目
2. 点击菜单 **运行 > 运行到手机或模拟器 > 制作自定义基座**
3. 等待基座制作完成（首次需要几分钟）
4. 制作完成后，选择 **使用自定义基座**

> **关键**：Vue3 项目**不能用标准基座**，必须制作并使用自定义基座。

### 步骤四：运行到手机

1. 用数据线连接安卓手机
2. 开启手机的 **USB 调试** 模式
3. 在 HBuilderX 中点击 **运行 > 运行到手机或模拟器 > 运行到 Android App 基座**
4. 确保选择的是 **自定义基座**

## 问题 B 修复后的操作步骤

代码修复完成后，需要**重新运行项目**才能生效：

### 方法一：HBuilderX 中重新运行
1. 在 HBuilderX 控制台点击 **停止运行**
2. 重新点击 **运行 > 运行到手机或模拟器**
3. 进入 AI 聊天页面，发送一条消息测试

### 方法二：如果问题仍然存在

#### 确认后端 AI 相关接口可用

在电脑浏览器中访问以下地址，确认返回正常：

```
http://localhost:8080/api/sessions
```
> 应该返回 JSON 数组（可能为空 `[]` 或包含已有会话）

如果返回错误或无法访问：
1. 确认 Spring Boot 后端已启动（IDEA/Eclipse 中运行主类）
2. 确认 MySQL 数据库已启动且数据库 `bookkeeping_book` 存在
3. 确认端口 8080 没有被其他程序占用

#### 在手机浏览器中验证网络可达性

用安卓手机浏览器访问：

```
http://192.168.101.84:8080/api/sessions
```

> 如果能返回数据，说明网络通畅。如果打不开，检查：
> - 手机是否连接的**同一 WiFi**（不是移动数据）
> - Windows 防火墙是否允许 Java/Node 入站（见下方防火墙配置）

#### Windows 防火墙放行 8080 端口

```powershell
# 以管理员身份运行 PowerShell
netsh advfirewall firewall add rule name="Allow Port 8080" dir=in action=allow protocol=tcp localport=8080
```

或者手动操作：
1. 打开 Windows 设置 → 更新和安全 → Windows 安全中心 → 防火墙和网络保护
2. 点击 **高级设置**
3. 选择 **入站规则** → **新建规则**
4. 选择 **端口** → TCP → 特定本地端口填 `8080` → 允许连接

## 如果仍有问题

### 检查 1：manifest.json 中的 appid

确认 `manifest.json` 中的 `appid` 不是 `__UNI__XXXXXX` 这种测试 ID。如果是，建议：

1. 登录 [DCloud 开发者中心](https://dev.dcloud.net.cn/)
2. 创建一个新的应用，获取正式 appid
3. 替换 `manifest.json` 中的 `appid`

### 检查 2：检查是否有报错信息

在 HBuilderX 控制台查看运行日志，是否有以下错误：

- `找不到模块 @dcloudio/uni-app-plus`
- `编译失败`
- `基座版本不匹配`

### 检查 3：网络连接

真机运行时，App 会连接 HBuilderX 进行热更新。确保：

1. 手机和电脑在同一局域网
2. 防火墙没有阻止 HBuilderX 的端口
3. 如果通过 USB 连接，确保 USB 调试正常

### 检查 4：基座兼容模式

如果自定义基座也无法运行，尝试在 `manifest.json` 的 `app-plus` 中添加：

```json
"app-plus": {
    "renderer": "native",
    "nvue": {
        "flex-direction": "column"
    }
}
```

> 注意：这仅在使用 nvue 页面时需要，普通 Vue 页面不需要。

### 检查 5：清除缓存重新运行

1. 删除手机上的基座应用
2. 删除项目中的 `unpackage` 目录
3. 重新制作自定义基座
4. 重新运行

## 替代方案：云打包

如果本地运行始终有问题，可以使用 DCloud 的云打包服务：

1. 在 HBuilderX 中点击 **发行 > 原生 App-云打包**
2. 选择 Android 平台
3. 使用 DCloud 公用证书（测试用）或上传自己的证书
4. 等待云端打包完成，下载 APK 安装到手机
