# 05 · AI 接口规范（/api/ai/**）

> 依据源码：`Controller/AiController.java`（584 行转发控制器，本次迁移等价于**把这些转发收敛为 FastAPI 进程内调用**）、`chatbot-server/index.ts`（Express 实际路由与响应）、`chatbot-server/db.ts`（数据行为）。
> 前端调用：`personal-ledger-frontend/src/pages/AiChat.jsx`、`src/components/AiChatDrawer.jsx`、`src/api/ai-session.js`、`src/pages/AiChat.jsx`（fetch SSE）。
>
> **⚠️ 三大铁律（违反即前端崩）**：
> 1. `/api/ai/**` 一律**返回裸 JSON，禁止套 `Result`**。
> 2. 会话/消息时间戳为 **int 毫秒**（不是 ISO 字符串），`createdAt/updatedAt/deletedAt/timestamp` 皆是。
> 3. SSE 事件行必须是 `data: <JSON>\n\n` 且 JSON 含 `type` 字段，取值 `content | done | error`。

## 0. 公共约定

- 鉴权：整个 `/api/ai` 路由挂 `Depends(get_current_user)`（Java `LoginInterceptor` 覆盖 `/api/**`）。未登录 → HTTP 401。
- 错误语义（对照 Java 转发行为，勿「规范化」）：除特别说明外，**业务错误用 HTTP 200 + body `{"error":"中文"}`**（Java 网关注入的 AI 接口业务失败时一律回 HTTP 200，错误只进 body；唯一例外是 `/api/ai/chat/stream` 缺参直写 HTTP 400）；会话归属/存在性错误通常表现为 `{error:"会话不存在"}` 或 `{success:false}`。前端对非 2xx 会走 axios reject / 弹错误，对 `{error}` 则自行读取。保持这一双轨即可。

内部数据结构定义见 06；本文件只描述 HTTP 契约。

## 1. 会话管理

### 1.1 创建会话 `POST /api/ai/sessions`

请求体：`{"title":"新对话"}`（title 可空，默认「新对话」；服务端截断 50 字符）。
响应（裸 Session 对象）：
```json
{ "id": "session_1725700000000_ab12cd34x", "userId": 1, "title": "新对话",
  "autoTitle": 1, "createdAt": 1725700000000, "updatedAt": 1725700000000, "deletedAt": 0 }
```
实现：`user_id=当前用户` 写入 sessions；ID 生成格式 `session_{ms}_{随机}`（对应 JS `substring(2,11)`，随机段最长 9 位）。

### 1.2 会话列表 `GET /api/ai/sessions`

Query：

| 参数 | 默认 | 规则 |
|---|---|---|
| keyword | 空 | 命中 `s.title LIKE %kw%` 或存在 `messages.content LIKE %kw%` |
| sort | updated | 仅 `updated` / `created`，否则返回 `{"error":"sort 参数非法"}` |
| order | desc | 仅 `asc`/`desc`，否则 `{"error":"order 参数非法"}` |
| page | 1 | `<1 → 1` |
| size | 20 | 夹取 `1..100` |

响应（**`{items,total}`** 结构）：
```json
{ "items": [ { "id": "session_...", "title": "帮我分析本月消费", "preview": "你: 帮我分析本月消费",
    "messageCount": 2, "createdAt": 1725700000000, "updatedAt": 1725701000000 } ],
  "total": 1 }
```

语义（`db.ts listSessions`）：
- 仅统计 `deleted_at = 0 AND user_id = :uid`；
- `preview` = 会话**最后一条消息**（按 timestamp 升序的最后一条）：`role=="user" → "你: "`、否则 `"AI: "` 前缀，content 截断 50 字符；
- `messageCount` = messages 数量；排序 `sortCol DESC, id DESC`。

### 1.3 重命名 `PATCH /api/ai/sessions/{id}`

请求体：`{"title":"..."}`（trim 后 1~50 字符，否则 `{"error":"标题需 1-50 字"}`）。
响应（成功）：`{"success":true,"session":{<Session>}}`；失败 `{"success":false}`。
语义：仅本人且未删除可改名；改名后 **`auto_title=0`**（锁定，AI 不再覆盖）。

### 1.4 删除（软删）`DELETE /api/ai/sessions/{id}`

成功 `{"success":true}`；否则 `{"success":false}`。语义：`deleted_at = 当前毫秒`，非物理删除。

### 1.5 批量删除 `POST /api/ai/sessions/batch-delete`

请求体：`{"ids":["session_...", ...]}`
规则：ids **为空或超过 50** → `{"error":"单次最多删除 50 条"}`（Java 网关为合并判断：空数组同样返回该条，与 Express 层的「ids 不能为空」不同，对外口径以网关为准）；去重；仅删除本人且未删的。
成功：`{"success":true,"deleted":N}`。

### 1.6 会话消息 `GET /api/ai/sessions/{id}/messages`

响应（**裸数组**，按 timestamp 升序）：
```json
[ { "id": "msg_...", "sessionId": "session_...", "role": "user",
    "content": "帮我分析本月消费", "timestamp": 1725700000000 } ]
```
归属不合法（非本人/不存在/已删除）→ Java 返回空数组 `[]`（HTTP 200），保持该行为。

## 2. 对话接口

### 2.1 非流式对话 `POST /api/ai/chat`

> 兼容 UniApp 移动端（React 桌面端主用 2.2 流式）。

请求体：`{"sessionId":"...","message":"..."}`（缺参 → `{"error":"缺少参数"}`）。
响应（**注意与 Express 的 `{answer}` 不同，Java 已转为 `{content}`，本实现保持 `content`**）：
```json
{ "content": "本月支出较上月上升 12%..." }
```

实现流程（对应 Java `chat` → Express `/api/chat`）：
1. 内部取用户上下文 `ctx`（见 06 §2）；
2. 校验会话归属 → 失败 `{"error":"会话不存在"}`；
3. `ChatChain.chat(...)`（内部会把本轮 user 消息与 assistant 完整回复写入 messages，见 06 §3.2）。

### 2.2 流式对话 `POST /api/ai/chat/stream`（SSE）

请求体：`{"sessionId":"...","message":"..."}`。
缺参 → HTTP 400（Java 直写 400，无 body）。
成功 → HTTP 200，`Content-Type: text/event-stream`，随后逐事件输出；**整个链路必须 async**。

SSE 事件格式（精确字节级，来自 Node `streamChat` + Java 透传）：
```
data: {"type":"content","content":"这段"}

data: {"type":"content","content":"继续回复"}

data: {"type":"done"}

```
- 结束由 `{"type":"done"}` 表示；连接关闭。
- 出错（含 LLM 异常、会话不存在）发送 `{"type":"error","error":"<消息>"}` 后关闭连接。
- 关键头（含反向代理）：
  ```
  Content-Type: text/event-stream; charset=utf-8
  Cache-Control: no-cache
  Connection: keep-alive
  X-Accel-Buffering: no          # Java 已设；nginx 下避免缓冲（07）
  ```
- Java 踩坑注释提醒：字符必须按 UTF-8 字节写出，不要用 Latin-1 编码 writer —— FastAPI 的 `StreamingResponse` 无此问题，直接 yield 字符串即可。

后端流程（对应 Java `chatStream` / Node `streamChat`）：
1. 鉴权 + 会话归属校验（失败 → error 事件）；
2. 构建 userContext（06 §2）；
3. 调 06 §3.1 `streamChat`，把每个增量 `yield f"data: {json.dumps({'type':'content','content':chunk}, ensure_ascii=False)}\n\n"`；
4. `onDone` 后 `yield data: {"type":"done"}` 并结束；若会话 `autoTitle==1`，**异步**生成标题（不阻塞 SSE 结束，06 §3.4）；
5. 异常时 `yield data: {"type":"error","error":...}` 后结束。

实现形态（务必 async 生成器）：
```python
from fastapi.responses import StreamingResponse

@app.post("/api/ai/chat/stream")
async def chat_stream(body: ChatStreamIn, user: CurrentUserDep, db=Depends(get_db_session)):
    if body.sessionId is None or body.message is None:
        return Response(status_code=400)
    ...
    async def gen():
        try:
            async for chunk in chat_chain.stream_chat(...):
                yield f"data: {json.dumps({'type':'content','content': chunk}, ensure_ascii=False)}\n\n"
            yield f"data: {json.dumps({'type':'done'})}\n\n"
        except Exception as e:
            yield f"data: {json.dumps({'type':'error','error': str(e)}, ensure_ascii=False)}\n\n"
    return StreamingResponse(gen(), media_type="text/event-stream", headers={...})
```

## 4. FAQ 与反馈

### 4.1 FAQ 语义检索 `GET /api/ai/faq/search?query=`

成功：`{"results":[{"id":1,"question":"...","answer":"...","category":"...","score":0.87}]}`（score 为相似度 0~1；检索器内部 Embedding 不可用时自动降级关键词检索，score 仍为 0~1 数字，响应**不含 fallback**）。
异常兜底：`{"results":[],"fallback":true}`（对应 Java 网关与 Express 路由 catch，任何失败都回此形态）。
实现语义（06 §5）：余弦相似度 > 阈值(默认 0.5) 取 topK(3)，按分降序；`rebuild` 后全量重建。

### 4.2 重建 FAQ 向量索引 `POST /api/ai/faq/rebuild`

成功 `{"success":true,"count":8}`；失败 `{"error":"重建失败","detail":"..."}`。

### 4.3 保存反馈 `POST /api/ai/feedback`

请求体：`{"messageId":"msg_...","rating":5,"comment":"很好"}`。
成功 `{"success":true}`；失败 `{"error":"保存失败"}`。对应 `db.addFeedback`（id=`feedback_{ms}_{rand}`，timestamp 毫秒）。

### 4.4 AI 会话统计 `GET /api/ai/admin/stats`

响应：`{"totalSessions":0,"totalMessages":0,"totalFeedback":0,"averageRating":0}`（全量 COUNT / AVG(rating)，无数据为 0）。

> 提示（B2）：Express 另有 `/api/admin/conversations`、`/api/admin/satisfaction` 两个 Java **从未转发**的死接口。若你的管理后台前端没有调用它们，可暂不迁移（前端 `api/admin.js` 仅用到 04 的 `/api/admin/*`）；若确认要补，按 Express 响应格式实现（见 `db.ts getAllConversations/getSatisfactionStats`）。

## 6. 自然语言记账 `/api/ai/bookkeeping`

> **新增能力**（本文档 §1–§5 为存量迁移契约，本节为纯新增）。
> 用户发一句口语化中文（"我今天花79块吃了一顿烤肉"），服务端做语义解析 → 字段归一化 → 校验 → 写入 `records` → 回显确认卡；缺金额时追问，非消费类消息不处理。
> 内部实现（Pydantic 模型、Prompt、金额/日期/分类归一化）见 **06 §11**；幂等日志表 DDL 见 **02 §3.5**；端点骨架见 **10 §6.15–§6.17**。
>
> ⚠️ **铁律继承**：本节接口同属 `/api/ai/**`，**一律裸 JSON，禁止套 `Result`**；业务失败用 **HTTP 200 + `{"error":"中文"}`**（同 §0）；只有 `records` 表时间用 `yyyy-MM-dd`（业务表语义，非 AI 毫秒戳）。

### 6.0 通用约定

| 项 | 取值 |
|---|---|
| 鉴权 | 全部 `Depends(get_current_user)`，未登录 → HTTP 401 |
| 时区 | 固定 `Asia/Shanghai`（配置 `TZ`），不依赖服务器本地时区；前端可传 `now` 覆盖（仅联调/测试用） |
| 幂等 | 强幂等键 `clientMsgId` + 弱幂等 `dedupHash`（5 分钟窗口），见 §6.1.5 |
| 单条上限 | 一条消息最多识别 **10 笔**（`AI_BOOKKEEPING_MAX_ITEMS`），超出 → `{"error":"一次最多识别 10 笔消费，请分开发送"}` |
| 文本上限 | `message` 1–500 字（trim 后计） |
| 事务 | 解析结果的多笔记录**在同一事务内**写入；任一项抛异常整体回滚 |
| 审计 | 每次调用（含 ignored/clarify/duplicate）都写一条 `ai_bookkeeping_logs` |

`action` 枚举（响应顶层字段，前端据此分支渲染）：

| action | 含义 | 是否写 `records` |
|---|---|---|
| `created` | 已入账 | 是 |
| `clarify` | 信息不全，追问 | 否（草稿进 `ai_bookkeeping_logs`，`status=0`） |
| `duplicate` | 命中幂等，未重复入账 | 否 |
| `ignored` | 非消费类消息 | 否 |

### 6.1 自然语言记账 `POST /api/ai/bookkeeping`

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| message | string | 是 | 原始口语化文本，1–500 字 |
| sessionId | string | 否 | AI 会话 ID；传入时把 user/assistant 消息写入 `messages`，并维护「最近一笔」上下文（§6.4） |
| clientMsgId | string | 否 | 客户端生成的 UUID，**强幂等键**；重发同一条消息必须带同一个值 |
| draftId | int | 否 | 追问续写：把本次 `message` 补进 `ai_bookkeeping_logs.id=draftId` 的草稿 |
| dryRun | bool | 否（默认 false） | true = 只解析不入账，返回 `preview`（`action=clarify` 的同构结构，含 `parse.items`），用于前端"确认后再记"模式 |
| force | bool | 否（默认 false） | true = 跳过弱幂等窗口，强制再记一笔同一内容的消费 |
| now | string | 否 | ISO datetime，覆盖服务端"今天"，仅联调/测试用 |

```json
{
  "sessionId": "session_1725969000000_ab12cd34x",
  "message": "我今天花79块吃了一顿烤肉",
  "clientMsgId": "8f2c1a10-4c7e-4a52-9f3b-2d6e0c9a7b41",
  "dryRun": false
}
```

#### 6.1.1 `action=created`

```json
{
  "action": "created",
  "requestId": "bk_1725969000123_x1y2z3",
  "records": [
    { "id": 128, "amount": 79.00, "type": 1,
      "categoryId": 3, "categoryName": "餐饮",
      "recordDate": "2026-09-10", "remark": "烤肉" }
  ],
  "totalAmount": 79.00,
  "echo": "已记下：餐饮 ¥79.00 · 今天(2026-09-10) · 备注「烤肉」· 记录 #128\n回复「改成45块」可修改，回复「删掉」可撤销。",
  "warnings": [],
  "errors": [],
  "sessionId": "session_1725969000000_ab12cd34x",
  "messageId": "msg_1725969000456_q8w7e6"
}
```

多笔时 `records` 为数组，`echo` 带序号与合计（模板见 §6.5）。

#### 6.1.2 `action=clarify`（缺金额 / 金额不可识别）

```json
{
  "action": "clarify",
  "requestId": "bk_1725969000789_a1b2c3",
  "draftId": 1291,
  "question": "这笔消费的金额是多少？比如「35元」。",
  "missing": ["amount"],
  "preview": {
    "items": [
      { "amount": null, "amountRaw": null, "type": 1,
        "categoryName": "餐饮", "categoryId": 3,
        "date": "2026-09-10", "dateExpr": "今天",
        "remark": "吃了顿烤肉", "confidence": 0.58 }
    ]
  },
  "records": []
}
```

> 客户端下一步：携带 `draftId` + 用户补充的 `message` 再次调用本接口，服务端合并后入账。草稿有效期 **30 分钟**（`AI_BOOKKEEPING_DRAFT_TTL_SEC`），过期 → `{"error":"草稿已过期，请重新描述这笔消费"}`。

#### 6.1.3 `action=ignored`（非消费类）

```json
{
  "action": "ignored",
  "requestId": "bk_1725969000999_m4n5p6",
  "reason": "not_expense",
  "echo": "这不像一笔消费记录，我没有记账。想记账可以说「今天打车花了18块」。",
  "records": []
}
```

`reason` 取值：`not_expense`（闲聊/问候）、`query`（查询类，前端应转 `/api/ai/analyze/expenses` 或 `/api/records`）、`income_unsupported`（识别为收入但用户未开启收入记账）、`too_ambiguous`（语义过于模糊且无法提炼出追问点）。

#### 6.1.4 `action=duplicate`（命中幂等）

```json
{
  "action": "duplicate",
  "requestId": "bk_1725969000123_x1y2z3",
  "originRequestId": "bk_1725968999000_p0o9i8",
  "records": [ { "id": 128, "amount": 79.00, "categoryName": "餐饮", "recordDate": "2026-09-10", "remark": "烤肉" } ],
  "echo": "这条我已经记过啦（#128 · 餐饮 ¥79.00），没有重复记账。",
  "hint": "如果确实要再记一笔，请重新发送并带上 force=true。"
}
```

#### 6.1.5 幂等规则（必须实现）

1. **强幂等**：`clientMsgId` 非空 → 查 `uk_client_msg(user_id, client_msg_id)`；命中则直接返回首次结果，`action=duplicate`。
2. **弱幂等**：无 `clientMsgId` 时算 `dedupHash = SHA256(user_id + "|" + normalize(message))`，在 `AI_BOOKKEEPING_DEDUP_WINDOW_SEC`（默认 **300s**）窗口内查找同 `dedupHash` 且 `action='created'` 的日志 → 命中返回 `duplicate`。
   - `normalize`：去首尾空白、全角标点转半角、统一小写、压缩连续空白；**不动数字**。
3. **并发安全**：先 `INSERT` 日志（唯一键 `uk_request_id` / `uk_client_msg`）再写 `records`；捕获 `IntegrityError` → 回查首次结果 → `duplicate`。禁止"先 SELECT 判断再 INSERT"。
4. `force=true` 只跳过第 2 条，**不跳过第 1 条**（`clientMsgId` 是客户端承诺的重试语义）。
5. `dryRun=true` 不参与去重判定，也不产生可被去重的日志（`action='preview'`）。

#### 6.1.6 错误（一律 HTTP 200 + 裸 JSON）

| 场景 | 响应 |
|---|---|
| 缺 `message` 或 trim 后为空 | `{"error":"缺少参数: message"}` |
| `message` 超过 500 字 | `{"error":"消息过长，最多 500 字"}` |
| `sessionId` 不存在 / 非本人 / 已删除 | `{"error":"会话不存在"}` |
| `draftId` 不存在、非本人、已处理或过期 | `{"error":"草稿已过期，请重新描述这笔消费"}` |
| 解析出的条目超过 10 笔 | `{"error":"一次最多识别 10 笔消费，请分开发送"}` |
| LLM 调用失败 / 输出无法校验 | `{"error":"记账解析失败，请换个说法再试"}`（detail 不回显给前端，只写日志） |

### 6.2 修改刚记下的记录 `PATCH /api/ai/bookkeeping/{record_id}`

用于"用户通过后续消息修改"。两种修法**二选一**，都给时**以显式字段为准**。

请求体（至少一项非空）：

| 字段 | 类型 | 说明 |
|---|---|---|
| amount | number | >0，≤99999999.99，保留 2 位 |
| categoryId | int | 必须属于当前用户或系统预设，且 `type` 与原记录一致 |
| recordDate | string | `yyyy-MM-dd` |
| remark | string | ≤200 字，超出截断 |
| message | string | 自然语言修指令，如"改成45块5，备注AA"；由服务端解析出增量字段 |

```json
{ "message": "改成45块5" }
```

响应：

```json
{
  "success": true,
  "record": { "id": 128, "amount": 45.50, "type": 1, "categoryId": 3,
              "categoryName": "餐饮", "recordDate": "2026-09-10", "remark": "烤肉" },
  "changes": { "amount": { "from": 79.00, "to": 45.50 } },
  "echo": "已更新 #128：餐饮 ¥45.50（原 ¥79.00）· 2026-09-10 · 备注「烤肉」"
}
```

失败：非本人 / 不存在 / 已删除 → `{"error":"记录不存在"}`；字段非法 → `{"error":"<具体中文，同 04 §3.4>"}`。
每次修改在 `ai_bookkeeping_logs` 追加一条 `action='amend'`、`parent_id` 指向原记账日志，便于回溯"AI 记错—用户改对"的样本。

---

### 6.3 删除刚记下的记录 `DELETE /api/ai/bookkeeping/{record_id}`

```json
{ "success": true, "echo": "已删除 #128（餐饮 ¥79.00 · 2026-09-10）" }
```

- 语义与 `DELETE /api/records/{id}` 一致：**软删**（`records.status=0`）。
- 非本人 / 不存在 / 已删 → `{"error":"记录不存在"}`。
- 同样写 `ai_bookkeeping_logs`（`action='delete'`），并把原日志 `status` 置为 2（已回滚）。

### 6.4 与对话链路的联动（`lastRecordId` 解析）

用户在 `/api/ai/chat`、`/api/ai/chat/stream`、`/api/ai/bookkeeping` 中说出"改成45块""删掉刚那笔""刚才记错了"，按下表解析目标记录：

| 优先级 | 来源 | 规则 |
|---|---|---|
| 1 | 显式 ID | 文本中出现 `#128` / "编号128" → 直接定位 |
| 2 | 当前会话最近一笔 | `ai_bookkeeping_logs` 中 `session_id=当前会话 AND user_id AND action='created' AND status=1`，按 `id DESC` 取 1 |
| 3 | 用户级最近一笔 | 同上但不限 `session_id`，限定 **30 分钟内**（`AI_BOOKKEEPING_CONTEXT_TTL_SEC`） |
| 4 | 无 | 回 `{"action":"ignored","reason":"no_recent_record"}`，提示"没有找到刚记下的记录，可以告诉我编号，比如「#128 改成45块」" |

> 不改动 `sessions` 表结构：全部通过 `ai_bookkeeping_logs` 反查，避免动存量表。
> 流式接口中命中修正/删除意图时，agent 内部调 §6.2/§6.3，结果以 `{"type":"content"}` 事件回显，并在末尾追加 `{"type":"done"}`（不新增 SSE 事件类型，前端零改动）。

### 6.5 回显文案模板（服务端 `echo` 字段，前端可直接渲染）

单笔：

```
已记下：餐饮 ¥79.00 · 今天(2026-09-10) · 备注「烤肉」· 记录 #128
```

多笔：

```
已记下 2 笔：
1) 餐饮 ¥32.00 · 2026-09-10 · 买菜（#128）
2) 交通 ¥18.00 · 2026-09-10 · 打车（#129）
合计 ¥50.00
```

尾部固定追加：`回复「改成45块」可修改，回复「删掉」可撤销。`

有 `warnings` 时在首行后插入：`⚠️ 未识别到明确分类，已归入「其他」，可回复「改成餐饮」调整。`

金额格式：`¥` + 千分位 + 两位小数（`79.00` / `1,299.00`），由服务端格式化，前端不二次处理。

### 6.6 边界情况清单（实现与联调必测）

| # | 输入 | 期望 |
|---|---|---|
| 1 | "我今天花79块吃了一顿烤肉" | created，餐饮 ¥79.00，date=今天，remark=烤肉 |
| 2 | "昨天打车18，买菜32块5" | created ×2，按原文顺序，date=昨天 |
| 3 | "花了点钱吃饭" | clarify，`missing=["amount"]`，不做任何猜测 |
| 4 | "你好啊" / "今天天气不错" | ignored，`reason=not_expense` |
| 5 | "这个月花了多少" | ignored，`reason=query` |
| 6 | 同一条消息 5 秒内重发两次 | 第二次 `duplicate`，records 不新增 |
| 7 | 带同一 `clientMsgId` 隔天重发 | `duplicate`（强幂等不过期） |
| 8 | "七十九块" / "79元" / "79.5" / "1,299" / "1万2" | 均正确归一化为 79.00 / 79.00 / 79.50 / 1299.00 / 12000.00 |
| 9 | 无时间词 | date = 今天 |
| 10 | "上周三买的鞋320" | date = 上一个自然周的周三 |
| 11 | "3月5号买了本书89" 且今天 2026-09-10 | date = 2026-03-05（不指定年份时结果晚于今天则年份 -1） |
| 12 | "买了个奇怪的东西 45" | created，分类「其他」+ warning |
| 13 | 金额 = 0 或负数 | 该条进 `errors`，不落库；整条无合法项 → clarify |
| 14 | 金额 > 99999999.99 | 该条进 `errors`，不落库 |
| 15 | "工资到账8000" | 默认按 `type=2`（收入）入账；若该用户无收入分类 → clarify 提示 |
| 16 | 一条消息含 11 笔 | `{"error":"一次最多识别 10 笔消费，请分开发送"}` |
