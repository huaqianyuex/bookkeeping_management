## 0. 接口总表与公共约定

| 前缀 | 鉴权 | 说明 |
|------|------|------|
| `/api/user` | register/login 公开；其余需登录 | 用户中心 |
| `/api/categories` | 需登录 | 分类 |
| `/api/records` | 需登录 | 账单 |
| `/api/statistics` | 需登录 | 统计 |
| `/api/admin` | 需登录 + 管理员(role=1) | 管理后台 |

公共说明：
- 成功：`{"code":200,"message":"<见各接口>","data":...}`；data 可能为对象/数组/字符串/数字或 `null`。
- 失败：HTTP 状态 + `{"code":...,"message":"<中文>","data":null}`（映射见 03 §2）。
- 参数校验失败的消息要与 Java Bean Validation 的中文消息一致（下表「校验规则/失败消息」列）；FastAPI 侧建议按 03 §2 的 RequestValidationError handler 兜底，**并在端点内对关键字段用 `BizError(400)` 手动校验**以保证消息精确一致。
- 取当前用户：端点参数 `user: CurrentUserDep`（03 §4）。

## 1. /api/user

### 1.1 注册 `POST /api/user/register`（公开）

请求体（`RegisterDTO`）：

| 字段 | 类型 | 规则 | 失败消息（Java） |
|---|---|---|---|
| username | string | 非空；`^[A-Za-z0-9\u4e00-\u9fa5]{2,20}$` | 用户名不能为空 / 用户名需为2-20位中英文或数字组合 |
| password | string | 非空；`^\d{6}$` | 密码不能为空 / 密码需为6位数字 |

响应（data=UserVO）：
```json
{ "code": 200, "message": "注册成功", "data": { "id": 1, "username": "zhangsan",
  "avatarUrl": null, "role": 0, "createTime": "2026-09-08T10:00:00", "updateTime": "2026-09-08T10:00:00" } }
```

规则（`UserServicesImpl.register`）：
1. `username` 已存在 → `BizError("用户名已存在")`（HTTP 500）。
2. 密码 `hash_password()` 存 `password`；`role=0`；插入后由 DB 填时间戳。

### 1.2 登录 `POST /api/user/login`（公开）

请求体（`LoginDTO`）：`username`/`password` 均 @NotBlank。
响应：`{"code":200,"message":"登录成功","data":"<JWT 字符串>"}`。

规则：
- 用户不存在 → `BizError("用户未注册，请注册后登录")`（500）。
- `verify_password` 失败 → `BizError("密码错误")`（500）。
- 成功签发 `create_token(user.id)`。

### 1.3 当前用户信息 `GET /api/user/info`（需登录）

响应 data=UserVO（含 `avatarUrl`）。用户不存在 → 401「用户不存在」（Java 中 RuntimeException，但此时用户是从 token 解析的，正常必有；兜底即可）。

### 1.4 更新资料 `PUT /api/user/info`（需登录）

请求体（`UserProfileUpdateDTO`）：`username`，规则同注册。
响应 message=「资料更新成功」，data=UserVO。
规则：
- 新用户名与他人重复（`username <> 自己` 存在）→ `BizError("用户名已存在")`。
- 更新 `username` 同时由 DB `ON UPDATE` 刷新 `update_time`。

### 1.5 上传头像 `POST /api/user/avatar`（需登录）

- `Content-Type: multipart/form-data`，文件字段名 **`file`**（前端 `user.js` 如此）。
- 规则与失败消息（03 §5 `save_avatar`）：大小≤2MB / JPG|PNG / 扩展名 .jpg|.jpeg|.png；旧头像若以 `avatar_url_prefix` 开头则删除该文件，防止磁盘膨胀。
- 响应：`{"code":200,"message":"头像上传成功","data":UserVO(新avatarUrl)}`

### 1.6 修改密码 `PUT /api/user/password`（需登录）

请求体（`PasswordUpdateDTO`）：

| 字段 | 规则 | 失败消息 |
|---|---|---|
| oldPassword | @NotBlank | 原密码不能为空 |
| newPassword | `^\d{6}$` | 新密码不能为空 / 密码需为6位数字 |

规则：原密码校验失败 → `BizError("原密码错误")`；成功写新 hash，响应 `{"code":200,"message":"修改成功","data":null}`。

> 注：Java 中存在两份改密 DTO（`PasswordDTO` 规则 6-20 位 与 `PasswordUpdateDTO` 规则 6 位数字），`UserController` 用的是 **PasswordUpdateDTO（6 位数字）**。以本表为准。

## 2. /api/categories

> 表名/列名口径见 **02 §0**：本模块对应 `categories` 表（复数），时间列 `created_at` / `updated_at`。

所有接口需登录。返回 `Category` 对象（JSON 键）：`{id,name,type,icon,sortOrder,userId,createTime,updateTime}`。
其中 `type` 取值 **0=支出 / 1=收入**（前端硬约束，见 02 §0）；`userId` 为 `null` 时表示系统预设分类。

### 2.1 新增 `POST /api/categories`

请求体（`CategoryDTO`）：`name`（@NotBlank，分类名称不能为空）、`type`（@NotNull，**0支出/1收入**，分类类型不能为空）、`icon` 与 `sortOrder` 可选。
`userId` 由当前用户注入，不取前端。
响应：`{"code":200,"message":"新增成功","data":<Category>}`

### 2.2 列表 `GET /api/categories`

Query：`type` 可选（**0=支出 / 1=收入**）。
实现：`WHERE user_id=:uid AND status=1 [AND type=:type] ORDER BY sort_order, created_at DESC`。
> ⚠️ 只返回当前用户的自建分类 + 系统预设（`user_id IS NULL`）：`WHERE (user_id = :uid OR user_id IS NULL) AND status = 1`。
响应：data=Category 数组。

### 2.3 修改 `PUT /api/categories/{id}`

请求体同 2.1。归属校验：分类不存在或非本人 → `BizError("分类不存在")`。
响应：`{"code":200,"message":"修改成功","data":<Category>}`

### 2.4 删除 `DELETE /api/categories/{id}`

归属校验同上。响应：`{"code":200,"message":"删除成功","data":null}`
> ⚠️ **行为变更（B7′，见 02 §0）**：定稿方案给 `records.category_id` 建了 `ON DELETE RESTRICT` 外键，因此**删除仍有账单的分类会被数据库拒绝**（errno 1451），需先提示用户「该分类下有 N 条账单」或引导改挂到「其他」。
> 旧 Java 行为（B7）是「删除成功、历史账单 `category_id` 保留悬空」——两者不可兼得；若要保留旧行为，必须去掉该外键（`sql/init_mysql.sql` 末尾「变体 B」）。

## 3. /api/records

需登录。对应 `records` 表（复数）。`RecordVO` 对象（**JSON 键均为 camelCase**）：

| 字段（JSON 键） | 类型 | 说明 |
|---|---|---|
| id | int | |
| userId | int | |
| categoryId | int | |
| categoryName | string \| null | LEFT JOIN `categories.name` |
| categoryType | int \| null | LEFT JOIN `categories.type`（**0=支出 / 1=收入**） |
| type | int | `records.type`，**0=支出 / 1=收入**（与 categoryType 同一套语义） |
| amount | number | decimal(10,2)，定点 2 位 |
| remark | string \| null | ≤200 字 |
| recordDate | string | `yyyy-MM-dd`（库列名为 `date`，输出键为 `recordDate`） |
| createTime / updateTime | string | ISO datetime（库列 `created_at` / `updated_at`） |

> ⚠️ **`recordDate` 这个输出键不能改**：Web 端 `Records.jsx` 表格列 `dataIndex: 'recordDate'`、编辑回填 `dayjs(record.recordDate)`，uni-app 更是直接按 `recordDate` 分组（`groups[r.recordDate]`）。若输出成 `date`，列表日期列会空白、移动端分组直接崩。

### 3.1 分页列表 `GET /api/records`

Query：
| 参数 | 默认 | 说明 |
|---|---|---|
| page | 1 | ≥1 |
| size | 10 | ≥1 |
| categoryId | 可选 | 精确过滤 |
| month | 可选 | 形如 `2026-09`，`date LIKE '2026-09%'`（Java `likeRight` 等价） |

排序：`date DESC, created_at DESC`（库列名；旧库为 `record_date` / `create_time`）。
默认只查未删除的：`WHERE user_id=:uid AND status=1`。响应 data=PageResult（records 内为 RecordVO，每行补 categoryName/categoryType）。

响应示例：
```json
{ "code": 200, "message": "操作成功", "data": {
  "records": [ { "id": 10, "userId": 1, "categoryId": 3, "categoryName": "餐饮",
    "categoryType": 0, "type": 0, "amount": 25.50, "remark": "午餐", "recordDate": "2026-09-07",
    "createTime": "2026-09-07T12:00:00", "updateTime": "2026-09-07T12:00:00" } ],
  "total": 1, "pages": 1, "current": 1, "size": 10 } }
```

### 3.2 详情 `GET /api/records/{id}`

SQL（`RecordMapper.xml`）：`record r LEFT JOIN category c` 单行，输出 camelCase。归属不符 → `BizError("记录不存在")`（Java 先取后比对 userId）。

### 3.3 新增 `POST /api/records`

请求体（`RecordDTO`）：

| 字段（JSON 键） | 类型 | 规则 | 失败消息 |
|---|---|---|---|
| categoryId | long | @NotNull | 分类不能为空 |
| amount | number(Decimal) | @NotNull；> 0 且 ≤ 99999999.99 | 金额不能为空 / 金额必须大于0 |
| remark | string | 可选，≤ 200 字 | |
| recordDate | string | @NotNull，`yyyy-MM-dd`（Java `LocalDate.parse`） | 日期不能为空 |
| type | int | **可选**（0=支出 / 1=收入）；不传则由所选分类的 `type` 推导 | |

> ⚠️ **`type` 必须是可选**：Web 端 `Records.jsx` 与 uni-app 记账页提交的载荷都是 `{categoryId, amount, remark, recordDate}`，**不含 `type`**。若声明为必填会直接 **422**，账都记不了。

规则：分类存在且归属本人（或为系统预设），否则 `BizError("分类不存在")`。成功后返回完整 RecordVO（含 categoryName）。
响应 message=「新增成功」。

### 3.4 修改 `PUT /api/records/{id}`

请求体同 3.3。先校验记录归属（不存在/非本人 → 「记录不存在」），再校验新分类归属。响应 message=「修改成功」。

### 3.5 删除 `DELETE /api/records/{id}`

归属校验同上。响应 message=「删除成功」。

> **删除语义已变更为软删除**：`UPDATE records SET status = 0 WHERE id = :id`（旧 Java 是物理 `DELETE`）。理由：AI 自然语言记账的「撤销刚才那笔」需要可回溯，且 `ai_bookkeeping_logs.action='delete'` 要把原日志置 `status=2`。
> 因此所有列表/统计查询都要带 `status = 1`。若要恢复物理删除，需同步改 02 §2.4 与 10 §6.17。

> 汇总查询技巧：分页+补名可用两条 SQL：先分页查 record，再按 `category_id IN (...)` 一次性取分类构建映射（Java 是逐条 `selectById`，迁移可优化为 N+1→1+1）。

## 4. /api/statistics

需登录。月度/分类统计基于**当前用户**。

### 4.1 月度总览 `GET /api/statistics/monthly?year=&month=`

Query：year、month 必填（int）。

SQL（`RecordMapper.getMonthlyStats`）：
```sql
SELECT #{year} AS year, #{month} AS month,
       COALESCE(SUM(CASE WHEN c.type = 1 THEN r.amount ELSE 0 END), 0) AS totalIncome,
       COALESCE(SUM(CASE WHEN c.type = 0 THEN r.amount ELSE 0 END), 0) AS totalExpense
FROM records r LEFT JOIN categories c ON r.category_id = c.id
WHERE r.user_id = :uid AND r.status = 1
  AND YEAR(r.date) = :year AND MONTH(r.date) = :month
```
> 优化建议（等价改写，可走索引，见 02 §2.4）：`r.date >= 当月1日 AND r.date < 次月1日`。
> 表/列名口径：`records`（复数）、`date`（旧库为 `record_date`）、`status` 为软删标记。

响应 data：
```json
{ "year": 2026, "month": 9, "totalIncome": 15000.00, "totalExpense": 8230.50, "balance": 6769.50 }
```
`balance = totalIncome - totalExpense`（Java 在内存算）。无记录时各为 `0`。

### 4.2 分类统计 `GET /api/statistics/category?year=&month=&type=`

Query：`year`、`month` **必填**（缺失/非整数 → HTTP 400 参数错误）；`type` 可选，默认 `0`（0=支出，1=收入）。

SQL：同源按 `GROUP BY c.id, c.name ORDER BY amount DESC`（type 过滤见 `RecordMapper.getCategoryStats`）。

百分比规则（`StatisticsServiceImpl`）：`percentage = amount / SUM(amount) * 100`，`scale=1`，四舍五入 HALF_UP；总量为 0 时各分类 `percentage=0.0`。amount 保留两位（BigDecimal）。

响应 data 数组：
```json
[ { "categoryId": 3, "categoryName": "餐饮", "amount": 3210.00, "percentage": 39.0 } ]
```

## 5. /api/admin（管理后台）

需 `role == 1`。以下 `UserVO`（管理侧）Java 未填 `avatarUrl`（恒为 null），保持即可。

### 5.1 用户列表 `GET /api/admin/users?page=&size=&keyword=`

Query：page(1)、size(10)、keyword 可选（`username LIKE %kw%`）。排序 `create_time DESC`。
data=PageResult，记录 UserVO。

### 5.2 用户详情 `GET /api/admin/users/{id}`

不存在 → `BizError("用户不存在")`。

### 5.3 删除用户 `DELETE /api/admin/users/{id}`

事务内（Java `@Transactional`）：
1. 目标 role==1 → `BizError("不能删除管理员账户")`；
2. 删该用户 `record`、`category`、`user`。
响应 message=「删除成功」。

### 5.4 批量删除用户 `POST /api/admin/users/batch-delete`

请求体：`{"ids":[1,2]}`（`BatchDeleteDTO` @NotNull → ID列表不能为空）。
规则同 5.3，遇到管理员即中断报错 `"不能删除管理员账户: <username>"`（Java 行为：抛出即整体回滚）。

### 5.5 所有账单 `GET /api/admin/records`

Query：page(1)、size(10)、`type`(0/1)、`month`(`yyyy-MM` 前缀)、`userId`。
排序 `record_date DESC, create_time DESC`。
管理端记录字段（`AdminRecordVO`，注意**无 updateTime**）：`id, userId, username, categoryId, categoryName, categoryType, amount, remark, recordDate, createTime`。

> ⚠️ 既有缺陷（B6）说明：Java 在**分页后内存过滤 type**，导致单页数量与 total 不一致。建议迁移时在 SQL 层 `JOIN category` 过滤 `type`，使 `total` 正确 —— 这是**刻意行为改进**，前端无需适配（列表本就期望按 type 过滤）。

### 5.6 批量删除账单 `POST /api/admin/records/batch-delete`

请求体 `{"ids":[...]}`；循环删除（无归属限制，管理员全域操作）。message=「批量删除成功」。

### 5.7 系统概览 `GET /api/admin/statistics/overview`

data=AdminOverviewVO：`{totalUsers,totalRecords,totalIncome,totalExpense,totalCategories}`（Long/Decimal）。

Java 统计口径（`AdminServiceImpl.getOverview`）：
- 计数：`user/category/record` 表 COUNT；
- `totalIncome`/`totalExpense`：遍历全部 record，按其 `category.type`（1收入/0支出）累加 amount。

实现建议（避免 Java 的逐条 selectById 全表 O(n×m)）：
```sql
SELECT COALESCE(SUM(CASE WHEN c.type = 1 THEN r.amount ELSE 0 END),0) AS inc,
       COALESCE(SUM(CASE WHEN c.type = 0 THEN r.amount ELSE 0 END),0) AS exp
FROM record r LEFT JOIN category c ON r.category_id = c.id
```

## 7. 实现完成自查清单

- [ ] `POST /user/register` 与 `login` 不要求 token，其余全部要求（含 `/user/info`）
- [ ] 所有返回 data 的键为 camelCase，无 `_` 泄漏
- [ ] 时间格式无毫秒（DATETIME 秒精度）；`recordDate` 为 `yyyy-MM-dd`
- [ ] `amount` 输出非科学计数（Decimal 序列化为定点数）
- [ ] 多用户隔离：加一条「用一个无痕窗口开第二账号」验证互不可见
- [ ] 管理接口用非管理员账号访问返回 403「无管理员权限」
- [ ] `type`=0 支出 / =1 收入 语义与统计一致
