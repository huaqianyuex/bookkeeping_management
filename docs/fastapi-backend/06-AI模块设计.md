### 3.3 `stream_chat` 流程（对齐 JS，注意顺序）

```python
async def stream_chat(self, session_id, message, user_context, db, cb):
    full_response = ""
    try:
        # 1) FAQ 语义检索（可并行发起，检索失败静默为 []）
        # 2) 压缩后历史（history 在落库前取，故不含本轮 user 消息）
        history = await get_messages_for_llm(db, session_id,
                                             max_tokens=settings.max_history_tokens,
                                             keep_recent=settings.keep_recent_messages)
        # 3) 落库本轮 user 消息（LLM 失败也不丢提问）
        await add_message(db, session_id, "user", message)
        # 4) 组装 faq_context（检索到 → "\n\n## 相关知识库参考:\nQ:..\nA:.."）
        # 5) 构建 Chain 并 astream
        prompt = build_prompt(system_context=self._format_user_context(user_context),
                              faq_context=faq_context)
        chain = prompt | self.llm | StrOutputParser()
        async for chunk in chain.astream({"input": message, "history": history,
                                          "systemContext": ..., "faqContext": faq_context}):
            full_response += chunk
            await cb.on_chunk(chunk)
        # 6) 落库 assistant 完整回复（即使中间出错只要有 partial 也落）
        await add_message(db, session_id, "assistant", full_response)
        await cb.on_done()
    except Exception as e:
        if full_response:
            await add_message(db, session_id, "assistant", full_response)
        await cb.on_error(e)
```

`_format_user_context`：复刻 JS `formatUserContext` 文本块（"## 用户当前财务数据 / ### 本月概况 (date) / - 总收入: ¥... / ### 支出分类 / - 餐饮: ¥3210 (39.0%) / ### 最近交易 / - [2026-09-07] 支出 | 餐饮: ¥25.5 (午餐)"；储蓄率 `(收入-支出)/收入*100` 保留 1 位，仅当 income>0）。

### 3.4 `chat`（非流式）与 `generate_title`

- `chat`：同上但一次性 invoke，落库 user+assistant，返回字符串。FAQ 注入格式为 JS `chat()` 版本：`"\n\n## 相关知识:\n" + answers.join("\n")`。
- `generate_title`：取该会话前 4 条消息找首个 user 消息；`asyncio.wait_for(self.llm.ainvoke(提示), 5.0)` 超时静默；提示词照搬：

```
请为以下对话生成一个不超过15个字的中文标题，只输出标题本身，不要引号：
{dialogue}
```

标题清洗：去首尾引号/空白，截 15 字；若会话 `auto_title==1` 才写回（`sessions.auto_title=1` 条件 UPDATE）。任何失败静默（不抛）。

```python
import re

def estimate_tokens(text: str) -> int:
    """移植 JS 估算：中文*0.75 + 英文词*1.3 + 数字串*0.5"""

    en = len(re.findall(r"[a-zA-Z]+", text))
    num = len(re.findall(r"\d+", text))
    return math.ceil(ch * 0.75 + en * 1.3 + num * 0.5)
```

## 6. FAQ 检索器（`app/ai/faq_retriever.py`）

### 6.1 流程

```python
class FAQRetriever:
    def __init__(self):
        self.embeddings = build_embeddings()
        self.entries: list[dict] = []      # {id,question,answer,category,embedding:list[float]}
        self.embedding_available = True
        self.index_path = settings.faq_vector_file   # 默认 data/faq_vectors.json

    async def initialize(self): ...
    async def search(self, query: str, top_k: int | None = None) -> list[dict]: ...
    async def rebuild(self) -> int: ...
```

- `initialize`：若 `faq_vectors.json` 存在则加载；否则从 `faq` 表取全部，逐批（≤20）`embedDocuments` 生成向量（batch 防超时，对应 JS batchSize=20），写索引文件；Embedding 不可用 → `embedding_available=False` 仅保留文本，降级关键词。
- `search`：`embedQuery(query)`，与全量条目算余弦（阈值 `faq_similarity_threshold`=0.5，取 topK）；降级走关键词。
- 关键词降级（**修复 JS 的 `searchFAQ` SQL bug（B1）**）：分词=`question+answer` 文本含该词 +1、标题含整句 +2，取 topK 后 `score/3` 归一化到 0~1；数据库兜底查询应为
  `SELECT id, question, answer, category FROM faq WHERE question LIKE :q OR answer LIKE :q LIMIT 5`。

```python
def cosine(a: list[float], b: list[float]) -> float:
    if not a or not b or len(a) != len(b): return 0.0
    dot = sum(x * y for x, y in zip(a, b))
    na = sum(x * x for x in a) ** 0.5
    nb = sum(x * x for x in b) ** 0.5
    return dot / (na * nb) if na and nb else 0.0
```

## 8. Prompt 大括号转义等 Python 陷阱（实现红线）

| 陷阱 | 说明 | 对策 |
|---|---|---|
| ChatPromptTemplate 字面 `{`/`}` | 模板变量是 `{var}`；**字面量花括号需写 `{{`/`}}`**，否则 `KeyError` | Prompt 中凡需输出 JSON 示例等用双括号 |
| Decimal/float 拼接 | 金额给 LLM 时转 float 文本；不要直接把 `Decimal` 丢给 f-string | `format_amount()` 统一 `float(x)` |
| `str | None` 兼容 | 用 `Optional[str]` 兼容 Python 3.10 | 本项目 3.11 可直接 `|` |
| 会话归属判断 | JS 以 `deletedAt !== 0` 拒绝；迁移后用 `deleted_at != 0` 等价过滤 | 所有会话读取统一加条件 |

## 9. 轻量对照实现（openai SDK + httpx，不依赖 langchain-*）

### 9.1 对话流式（openai SDK AsyncOpenAI）

```python
import json
from openai import AsyncOpenAI
from app.core.config import get_settings

client = AsyncOpenAI(api_key=s.agnes_api_key, base_url=s.openai_base_url)

def build_msgs(system_context: str, faq_context: str, history: list, input_: str) -> list[dict]:
    # system_context/faq_context 合并进一条 system 消息（占位替换后整段拼接），
    # history 展开为 user/assistant 消息，最后 append {"role":"user","content":input_}
    ...

async def stream_chat(messages: list[dict]) -> AsyncIterator[str]:
    stream = await client.chat.completions.create(
        model=settings.chat_model, messages=messages, temperature=0.7, stream=True)
    async for chunk in stream:
        if chunk.choices and chunk.choices[0].delta and chunk.choices[0].delta.content:
```

### 9.3 Embedding + 检索

## 11. 自然语言记账链（`app/ai/bookkeeping_chain.py` + `app/ai/normalizers.py`）

> 对应接口契约 **05 §6**；表 `ai_bookkeeping_logs` 见 **02 §3.5**；端点骨架见 **10 §6.15–§6.17**。
> 设计原则：**LLM 只做"抽取与意图判断"，所有数值/日期/分类的定型与校验由确定性代码完成**。LLM 输出的金额、日期一律视为"候选字符串"，必须过归一化 + 校验才能落库；归一化失败即追问，绝不猜。

### 11.1 Pydantic 输出模型

```python
from enum import Enum
from pydantic import BaseModel, Field


class BookkeepingIntent(str, Enum):
    bookkeeping = "bookkeeping"   # 记一笔/多笔
    amend       = "amend"         # 修改刚记下的
    delete      = "delete"        # 删除刚记下的
    query       = "query"         # 查询/统计类
    chitchat    = "chitchat"      # 闲聊


class BookkeepingItem(BaseModel):
    amount_raw:    str | None = Field(None, description="原文金额片段，如 '79块'/'七十九'")
    category_hint: str | None = Field(None, description="分类线索词，如 '吃饭'/'打车'，无则 null")
    date_expr:     str | None = Field(None, description="原文时间片段，如 '昨天'/'上周三'，无则 null")
    remark:        str | None = Field(None, description="从原文提炼的简短备注，≤20 字")
    is_income:     bool       = Field(False, description="是否为收入（工资/红包/报销到账等）")
    confidence:    float      = Field(..., ge=0, le=1, description="该条抽取的置信度")


class BookkeepingParse(BaseModel):
    intent:              BookkeepingIntent
    is_expense_related:  bool = Field(..., description="false 表示与消费/收入无关，直接 ignored")
    items:               list[BookkeepingItem] = Field(default_factory=list)
    clarify_question:    str | None = Field(None, description="需要追问时的问句")
    note:                str | None = Field(None, description="解析说明，调试用")
```

落库前的中间结构（归一化 + 校验之后）：

```python
@dataclass
class NormalizedItem:
    amount: Decimal          # 已 quantize 到 0.01
    type: int                # 0 支出 / 1 收入（Record.type，与 Category.type 同一套）
    category_id: int
    category_name: str
    date: date               # 对应 records.date（库列名就是 date）
    remark: str | None
    warnings: list[str]
    ok: bool                 # False → 进 errors[]，不落库
    error: str | None
```

### 11.2 Prompt

system（注意：模板里的字面花括号需按 §8 转义，改用 f-string 之外的 `.format` 或直接拼接）：

```
你是记账助手，负责从用户的口语化中文里抽取记账要素。只做抽取，不要计算、不要编造。

抽取规则：
1. amount_raw：原样截取金额片段（含单位）。没有出现任何金额信息时置 null，禁止推测。
2. category_hint：给出最能说明用途的关键词（如 吃饭/打车/买菜/房租/电影/药/学费）。判断不出置 null。
3. date_expr：原样截取时间片段（今天/昨天/前天/上周三/3月5号/N天前）。没有时间词置 null。
4. remark：从原文提炼 ≤20 字的备注，去掉金额和时间词；提炼不出则复制原文前 20 字。
5. is_income：工资、薪水、红包、报销、退款、利息、兼职收入等进账类置 true。
6. 一条消息含多笔消费时，items 按原文出现顺序输出多项；不要把多笔合并成一笔。
7. 闲聊、问候、查询账单（"这个月花了多少"）、设置预算等 → intent 对应 query/chitchat，items 为空。

输出要求：
- 严格 JSON，字段与给定 schema 完全一致。
- 用户没说金额时 amount_raw 必须是 null，宁可追问也不要猜。
- items 最多 10 项。
```

human 模板：

```
用户消息：{message}

当前日期（用于理解相对时间，仅作参考，不要直接输出）：{today}
用户已有分类（优先从这些里选，判断不出置 null）：{category_names}
```

> `today` 由服务端按 `Asia/Shanghai` 计算后注入（或取请求体 `now`），**不要让 LLM 自己猜今天是几号**。

### 11.3 金额归一化 `normalize_amount(raw) -> Decimal | None`

`app/ai/normalizers.py`，纯函数、无 IO、必须单测覆盖。

| 输入片段 | 输出 | 说明 |
|---|---|---|
| `79` / `79块` / `79元` / `79块钱` / `¥79` / `79 RMB` | `79.00` | 阿拉伯数字 + 单位 |
| `79.5` / `79.50元` | `79.50` | 小数 |
| `1,299` | `1299.00` | 千分位 |
| `七十九块` | `79.00` | 中文小写数字 |
| `三十五块五` / `35块5` | `35.50` | 「块/元」后接单数字 = 角 |
| `两百` / `二百` | `200.00` | 「两」按 2 |
| `1万2` / `1万2千` | `12000.00` | 万/千/百 单位进位 |
| `柒拾玖元整` | `79.00` | 中文大写（基础支持，不做金融级严谨校验） |
| `一共79` / `花了79` | `79.00` | 前置动词只作定位，不影响数值 |
| `0` / `0元` / `-5` | `None` | 非法：非正数 |
| `100000000` | `None` | 超出 `DECIMAL(10,2)` |
| `花了点钱` / `没多少` | `None` | 无法识别 → 触发追问 |
| `79块左右` / `大概80` | `79.00` / `80.00` | 模糊词忽略（并在回显里不加备注） |

要点：

```python
from decimal import Decimal, ROUND_HALF_UP, InvalidOperation

MAX_AMOUNT = Decimal("99999999.99")

def normalize_amount(raw: str | None) -> Decimal | None:
    if not raw:
        return None
    # 1) 全角→半角；去空格；统一 rmb/人民币/块钱/块/元
    # 2) 中文数字（含大写、含 万/千/百/十）→ 阿拉伯数字（可引 cn2an，也可自写 40 行映射）
    # 3) 正则抓数值：r'(\d+(?:[.,]\d+)*)' 与「块/元」后的角位数字
    # 4) Decimal(str(v)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
    # 5) 0 < v <= MAX_AMOUNT 才返回，否则 None
```

- **必须**用 `Decimal`，禁止 float 参与金额运算（02 §1「禁止 float/double 存钱」）。
- 中文数字转换可引第三方 `cn2an`（同步补进 01 §3 依赖清单）；若不引依赖，自写映射即可覆盖 99% 场景。
- 返回 `None` 时不猜、不取默认值，直接标记 `need_clarify`。

### 11.4 日期归一化 `normalize_date(expr, today) -> date`

| 表达 | 结果（`today = 2026-09-10`，周四） |
|---|---|
| 今天 / 今日 / 今天中午 | `2026-09-10` |
| 昨天 / 昨日 | `2026-09-09` |
| 前天 | `2026-09-08` |
| 大前天 | `2026-09-07` |
| 明天 | `2026-09-11`（允许，加 warning「记的是未来日期」） |
| 本周三 / 这周三 / 周三 | `2026-09-09`（本周内 weekday=3） |
| 上周三 | `2026-09-02`（上一自然周，周一为一周起点） |
| 上周一 / 上周末 | `2026-08-31` / `2026-09-06` |
| 本周 / 这周 / 上周 | 取该周周一（`2026-09-07` / `2026-08-31`） |
| 上个月 / 上月 | 上月 1 号 `2026-08-01` |
| 3月5号 / 3月5日 | `2026-03-05`（不指定年份时，结果晚于今天 → 年份 -1） |
| 12月25号 | `2025-12-25`（晚于今天 → 去年） |
| 5号（无月份） | 本月 5 号；若晚于今天则上月同日；仍越界取该月最后一天 |
| 3天前 / N天前 | `today - N` |
| 半年前 | `today - 182`（近似，加 warning） |
| 昨天下午三点 | 忽略时段，取 `2026-09-09` |
| 无时间词 / 无法识别 | `today`（加 warning「未识别到日期，已按今天记录」） |

要点：

- 时区固定 `Asia/Shanghai`：`today = datetime.now(ZoneInfo("Asia/Shanghai")).date()`，请求体 `now` 可覆盖（测试用）。
- 年份补齐规则：结果 `> today` 且原文未指定年份 → 年份 -1（避免记出未来账单）；收入类同样适用。
- 结果越界（`today - 10年` ~ `today + 1年`）→ 回落 `today` + warning。
- 输出 `date` 对象，落库前转 `yyyy-MM-dd` 字符串（与 04 §3 `recordDate` 一致）。

### 11.5 分类解析 `resolve_category(db, user_id, hint, type) -> (category_id, name, warning)`

按序匹配，**首次命中即返回**：

1. **归一化**：`hint` 去空格、繁转简、大写转小写。
2. **精确匹配**：在可见分类（`user_id = 0` 系统预设 **或** `user_id = :uid` 自定义，且 `type` 与本次一致、`status = 1`）中按 `name` 精确相等匹配；**自定义优先于系统预设**。
3. **别名表**：内置映射表命中即返回（下表为种子，可持续扩充，建议落 `app/ai/category_alias.py`）：

   | 别名关键词 | 分类 |
   |---|---|
   | 吃饭/午饭/晚饭/早餐/外卖/烤肉/火锅/奶茶/咖啡/聚餐/零食/买菜 | 餐饮 |
   | 打车/滴滴/地铁/公交/高铁/机票/加油/停车/共享单车 | 交通 |
   | 买衣服/淘宝/京东/拼多多/日用品/超市/数码/化妆品 | 购物 |
   | 电影/剧本杀/KTV/游戏/旅游/健身/演唱会 | 娱乐 |
   | 房租/水电/物业/宽带/燃气/房贷 | 住房 |
   | 看病/买药/挂号/体检/医保 | 医疗 |
   | 学费/买书/网课/考试/培训 | 教育 |
   | 话费/会员/订阅/云盘 | 通讯 |
   | 工资/薪水/奖金 | 收入 · 工资 |
   | 红包/报销/退款/利息 | 收入 · 其他 |

4. **模糊匹配**：上面都没中时，对可见分类名做包含匹配（`hint in name or name in hint`），唯一命中才采用；多个命中则弃用。
5. **历史行为**：查该用户近 90 天 `records` 中 `remark` 与 `hint` 相似度最高且使用过的 `category_id`（≥3 次才采信）。可选增强，默认开启。
6. **兜底**：取系统分类「其他」（`user_id=0 AND type=:type AND name='其他'`）；若该分类缺失 → 取该用户 `type` 匹配的第一个分类；再无 → 该条 `ok=False`，`error="没有可用的分类，请先创建分类"`。
   **兜底必须带 warning**：「未识别到明确分类，已归入「其他」」。

> ⚠️ **`category.type` 与 `record.type` 现在是同一套语义：`0 = 支出 / 1 = 收入`**（02 §0 定稿）。
> 这是前端硬约束——Web 端 `categories.filter(c => c.type === 0)` 取支出分类、`categoryType === 0 ? '-' : '+'` 判正负号，uni-app 同理。因此转换函数极简：`record_type = category_type = 0 if is_income is False else 1`。
> （历史坑：Java 时代 `Category.type` 是 0/1 而代码里曾把 `Record.type` 写成 1/2，两个 type 语义不同；该错误已废弃，**不要再按 1/2 转换**。）

### 11.6 落库流程 `commit_bookkeeping(db, user_id, items) -> (records, errors)`

```
parse（LLM，JSON mode）
  └─ intent=query/chitchat 或 is_expense_related=false → action=ignored，写日志，返回
       └─ items 为空 → action=clarify（无金额/无要素），写草稿日志 status=0
            └─ 逐条 normalize_amount / normalize_date / resolve_category
                 ├─ amount 为 None        → ok=False, error="未识别到金额"
                 ├─ amount 不合法         → ok=False, error="金额必须大于 0 且不超过 99999999.99"
                 ├─ category 无可用       → ok=False, error="没有可用的分类，请先创建分类"
                 └─ date 越界             → 回落 today + warning（不判失败）
            └─ ok=True 的项：同一事务内逐条 INSERT records（type/category_id/amount/date/remark/status=1）
            └─ 全部 ok=False → 不写库，action=clarify，question 取第一条的追问话术
            └─ 部分成功     → action=created，errors[] 列出失败项
       └─ 写 ai_bookkeeping_logs（record_ids / parse_json / action / status）
```

- 多笔**分别入账**、各自返回 `id`；数量上限 10（超出直接报错，不静默截断）。
- 追问话术按缺失字段生成：`amount` → 「这笔消费的金额是多少？比如「35元」。」；`category` 不触发追问（兜底「其他」）；`date` 不触发追问（兜底今天）。
- `dryRun=true` 时跳过 INSERT 与去重日志，只返回 `preview`。
