## 一、用户模块 `/api/user`

### 1.1 用户注册

- 请求方式：POST
- 路径：`/api/user/register`
- 是否需要登录：否

请求体：

```json
{
    "username": "zhangsan",
    "password": "123456"
}
```

请求参数说明：

| 字段     | 类型   | 必填 | 说明             |
| -------- | ------ | ---- | ---------------- |
| username | String | 是   | 用户名，不能重复 |
| password | String | 是   | 密码，6-20位     |

成功响应：

```json
{
    "code": 200,
    "message": "注册成功",
    "data": {
        "id": 1,
        "username": "zhangsan"
    }
}
```

失败场景：

| 场景         | code | message        |
| ------------ | ---- | -------------- |
| 用户名已存在 | 500  | 用户名已存在   |
| 用户名为空   | 400  | 用户名不能为空 |
| 密码为空     | 400  | 密码不能为空   |

实现提示：

- 需要新建 RegisterDTO 类接收参数
- 注册时密码要用 BCrypt 加密存储（不要明文存）
- 需要在 pom.xml 加 spring-boot-starter-security 依赖（仅用 BCrypt，不用整套安全框架）

## 四、统计模块 `/api/statistics`

### 4.1 月度收支汇总

- 请求方式：GET
- 路径：`/api/statistics/monthly`
- 是否需要登录：是

请求参数：

| 字段  | 类型    | 必填 | 说明          |
| ----- | ------- | ---- | ------------- |
| year  | Integer | 是   | 年份，如 2026 |
| month | Integer | 是   | 月份，如 5    |

成功响应：

```json
{
    "code": 200,
    "message": "操作成功",
    "data": {
        "year": 2026,
        "month": 5,
        "totalIncome": 8000.00,
        "totalExpense": 3500.00,
        "balance": 4500.00
    }
}
```

实现提示：

- SQL 需要用 SUM 聚合函数
- 按 type 区分收入和支出分别求和
- 要联表查 category 表获取 type

```sql
-- 参考 SQL（需要自己改成 MyBatis-Plus 写法或 XML 写法）
SELECT 
    c.type,
    SUM(r.amount) as total
FROM record r
LEFT JOIN category c ON r.category_id = c.id
WHERE r.user_id = #{userId}
    AND YEAR(r.record_date) = #{year}
    AND MONTH(r.record_date) = #{month}
GROUP BY c.type
```

```sql
-- 参考 SQL
SELECT 
    r.category_id,
    c.name as category_name,
    SUM(r.amount) as amount
FROM record r
LEFT JOIN category c ON r.category_id = c.id
WHERE r.user_id = #{userId}
    AND YEAR(r.record_date) = #{year}
    AND MONTH(r.record_date) = #{month}
    AND c.type = #{type}
GROUP BY r.category_id, c.name
ORDER BY amount DESC
```

## 六、拦截器设计（统一验证登录）

### LoginInterceptor.java

```java
/**
 * 作用：在请求到达 Controller 之前，统一检查有没有 token
 * 流程：
 *   1. 从请求头获取 Authorization
 *   2. 解析 token 得到 userId
 *   3. 把 userId 存到 ThreadLocal 里（方便后续代码获取）
 *   4. 如果 token 无效或过期，返回 401 错误
 */
```

### UserContext.java

```java
/**
 * 作用：用 ThreadLocal 存储当前登录用户的 userId
 * 方法：
 *   setUser(Long userId)   - 存入 userId
 *   getUser()              - 取出 userId
 *   remove()               - 清除（请求结束后必须调用，防止内存泄漏）
 *
 * 为什么要用 ThreadLocal？
 *   因为每个请求在独立的线程中处理，
 *   ThreadLocal 能保证每个线程只看到自己的数据，互不干扰。
 */
```

## DTO 和 VO 的区别（你可能会问）

```
DTO（Data Transfer Object）：前端传给后端的数据
    比如 RecordDTO，包含前端提交的 amount、remark、recordDate

VO（View Object）：后端返回给前端的数据
    比如 RecordVO，除了 record 本身的字段，还要加上 categoryName 等额外信息
```
