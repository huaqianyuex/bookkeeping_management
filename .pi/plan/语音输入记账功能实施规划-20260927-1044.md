# 语音输入记账功能实施规划

## 0. 结论先行

现有代码已具备**完整的文本自然语言记账能力**，语音功能**不新增任何解析与落库逻辑**，只需叠加三层：

1. **采集层**（uniapp）：录音 → 音频文件；
2. **识别层**（后端新增 STT 抽象）：音频 → 文本，provider 可替换；
3. **交互层**（uniapp）：识别文本回填 → 复用现有 `/api/ai/bookkeeping` 的 dry-run 预览做确认/纠错卡片。

复用的现成资产（不可重复造轮子）：
- `fast_backend/ai/bookkeeping_chain.py`：LLM 结构化抽取（金额/类别/日期/备注/收支类型/置信度）；
- `fast_backend/ai/normalizers.py`：金额/日期规则级清洗兜底（不猜测，缺金额触发 clarify）；
- `fast_backend/ai/category_alias.py`：分类名 ↔ 系统分类映射；
- `fast_backend/routers/ai.py` 中 `/api/ai/bookkeeping` 的 created/clarify/ignored/duplicate/dry_run 分支、幂等（clientMsgId + dedup_hash）、`PATCH/DELETE` 纠错链路；
- `ai_bookkeeping_logs` 审计表（幂等/追问草稿/纠错链）与 `records` 表（金额 DECIMAL(10,2)）；
- `fast_backend/utils/throttle.py`（节流）。

---

## 1. 功能范围

### MVP（本期）
- AI 助手页输入条新增**话筒按钮**：按住说话 → 松开结束 → 转写 → 文本回填输入框（可改）→ 发送；
- 发送走 `dry_run=true` 预览 → **确认卡片**（金额/分类/日期/备注 四字段可改）→ 确认入账；修改字段以 `overrides` 提交；
- 完整处理 clarify（缺金额追问续写）、duplicate（重复提示 + force 强记）、ignored（非记账降级对话）、低置信度强提示；
- 后端 `POST /api/ai/voice/transcribe`（认证 + 大小/时长/类型校验 + 节流 + 临时文件即用即删）；
- STT provider 抽象，默认 OpenAI 兼容 Whisper（复用现有网关与 Key），**切换只需改配置一行**。

### Phase 2（可选，本期不做）
- 账单页（`pages/records/index`）悬浮麦克风快捷入口（需将确认卡片独立成可复用页面）；
- Web 端（React）语音入口；客户端原生 ASR（微信同声传译插件）作为 STT 客户端 provider。

## 2. 总体数据流

```
┌─ 采集 ─┐ ┌────────── 识别 ──────────┐ ┌──── 解析（复用现有链）─────┐ ┌─ 确认/纠错 ─┐ ┌─ 落库（复用）─┐
│按住说话 │ │ POST /api/ai/voice/      │ │ POST /api/ai/bookkeeping  │ │ 确认卡片     │ │ created:      │
│录音 60s │→│ transcribe               │→│ dryRun=true → preview     │ │ 改字段→      │ │ INSERT        │
│(m4a/mp3)│ │  STTProvider 转文本      │ │ (bookkeeping_chain +      │ │ overrides    │ │ records × n   │
│         │ │  文本+置信度            │ │  normalizers +            │ │ 确认→create  │ │ + 审计日志     │
└─────────┘ └─────────────────────────┘ │  category_alias)          │ └──────────────┘ │ + echo 气泡    │
                                        └──────────────────────────┘                   └───────────────┘
```

关键决策：**转写只产生文本，一切记账语义仍走现有文本管线的同一入口**，保证同一条语料「语音说」与「手输」的支行为完全一致（含幂等/追问/纠错审计）。

## 3. 各环节职责边界

| 环节 | 归属 | 职责 | 明确不做 |
|---|---|---|---|
| A. 采集 | uniapp 客户端 | 权限申请、录音（`uni.getRecorderManager`，上限 60s）、录音中动画/倒计时、生成临时音频 | 不做识别、不做解析 |
| B. 识别 | 后端新增 `ai/stt.py` | 校验上传（大小/类型/时长/节流）、调 STT provider、返回文本+置信度、**用完即删临时文件** | 不做语义解析、不落库音频 |
| C. 解析/字段映射 | 现有 `bookkeeping_chain + normalizers + category_alias`（新增 0 行解析代码） | 文本 → 结构化条目；金额缺失不猜测 | 不吞掉 LLM/服务异常（路由兜底 ai_error） |
| D. 确认/纠错 | uniapp 客户端 | dry-run 预览渲染、字段就地编辑、overrides 提交、clarify/duplicate/ignored 对应交互 | 不做二次解析（overrides 仅覆盖解析结果） |
| E. 持久化/审计 | 现有 `routers/ai.py` created 分支 + `ai_bookkeeping_logs` | INSERT records（Decimal）；日志记 source/record_ids/parent_id | 不改 `records` 表结构 |

## 4. 详细设计

### 4.1 采集（A 层）

- 入口：AI 助手页输入条，发送按钮左侧新增圆钮话筒（`AppIcon` 新增 mic 图标或 CSS 内联）。
- 交互：**按下开始 / 松开结束**（`touchstart/touchend`），避免误触；录制中显示「正在聆听…」+ 波形/秒数（上限 60s 自动停止）。
- 权限：
  - App/H5：`uni.authorize({scope: 'scope.record'})`，拒绝时弹窗引导去设置；
  - `manifest.json`：Android 增加 `RECORD_AUDIO` 权限行；`mp-weixin` 段加 `"permission": {"scope.record": {"desc": "用于语音记账"}}`；App-iOS 加 `NSMicrophoneUsageDescription`（HBuilderX 打包配）。
- 参数（`uni.getRecorderManager().start({duration: 60000, sampleRate: 16000, numberOfChannels: 1, format: 'mp3'|'m4a'|'aac'（按平台），bitRate: 48000})`），结束回调取 `tempFilePath`。
- 异常：`onError`（授权拒绝/录音失败）→ toast「无法录音」并恢复按钮。


**可替换性约定**：新增 provider = 实现 `SttProvider` + 在 `get_stt_provider` 注册表加一行，前端与路由零改动。默认实现正好复用了项目既有的「OpenAI 兼容网关」模式（`OPENAI_BASE_URL/AGNES_API_KEY`），与 `ai/llm.py` 同构，私有化部署可直接指向任何兼容 `/audio/transcriptions` 的本地 Whisper 服务。

**新增端点 `POST /api/ai/voice/transcribe`**（挂 `routers/ai.py`，遵守 AI 模块铁律：裸返回、业务失败 `ai_error("中文")`、鉴权 401 由依赖抛）：
- 入参：multipart `file`（`UploadFile`）；出参裸 `{text, language, confidence}`；
- 校验链：登录 → 节流（复用 `utils/throttle.py`，每用户每分钟 `VOICE_RATE_LIMIT_PER_MIN` 次，超限 `ai_error("说话太频繁，请稍后再试")`）→ 大小 ≤ `STT_MAX_SIZE_MB` → 扩展名白名单（mp3/m4a/wav/aac）→ 时长异常由 provider 侧兜底（Whisper 不去重）；
- 临时文件写入服务临时目录（`tempfile.mkdtemp`，不进 `uploads/`，隐私），`try/finally` 保证转写后删除；**音频永不落库**；
- 转写空文本 → 返回 `{text: ""}`，由前端提示「没听清，请再说一次」；
- 服务异常 → 日志记 `error_msg`，返回 `ai_error("语音识别暂不可用，请稍后重试")`（不回显底层报错）。

### 4.3 解析与字段映射（C 层，零新增逻辑）

识别文本直接作为 `/api/ai/bookkeeping` 的 `message`，解析结果字段映射（均为现有行为，此处列出口径供验收）：

| 语音示例 | amount | category | date | remark | type |
|---|---|---|---|---|---|
| 「今天打车花了 18 块」 | 18.00 | 交通 | 今天 | 打车 | 0 支出 |
| 「周二超市买东西 58 元5」 | 58.50（normalizers 处理「元5」） | 购物 | 按今天推算到周二 | 超市买东西 | 0 支出 |
| 「上周三工资 8000 块」 | 8000.00 | 工资（收入侧） | 上周三 yyyy-MM-dd | 工资 | 1 收入 |

规则要点（复用，不重写）：金额缺失 → `clarify` 追问不猜测；分类匹配失败 → 归「其他」+ warnings；相对日期推算失败 → 回落今天；`ParsedItem.confidence` 低 → 确认卡强提示。

### 4.4 确认/纠错流程（D 层，新增前端交互）

**`BookkeepingIn` 新增两个可选字段**（向后兼容，文本记账不受影响）：
- `source: str = "text"` —— `"voice"` 标记语音来源，写入审计日志；
- `overrides: list[BookkeepingOverride] | None` —— 确认卡上用户改过的字段。每条含 `index`（对应 `parsed.items` 顺序）+ `amount/category_id/date/remark/type` 的可选子集。路由在构建 `ok_items` 后应用：金额/日期走 `normalizers` 同套校验（范围、格式），分类走归属+`type` 一致性校验（复用 amend 的校验逻辑），非法直接 `ai_error`。**不触发二次 LLM 解析**。

**交互状态机**（AI 助手页）：

```
按住说话 → 转写中 → 文本回填输入框（可编辑）→ 发送
  ├─ dry_run=preview(即试算) → 记账类(有 items)
  │     ├─ 全字段齐全 → 确认卡片：[¥金额|分类|日期|备注] + 置信度黄条(可选) + [修改][确认记账]
  │     │     ├─ 确认 → create(dryRun=false, 同 clientMsgId) → created echo 气泡 + 成功反馈
  │     │     └─ 修改 → 卡片内四字段就地编辑（金额用数字键盘，分类用现有分类网格，日期用 picker）→ 保存 → create + overrides
  │     └─ 全部缺金额 → clarify 气泡「这笔消费的金额是多少？」+ draftId 挂起
  │            ├─ 再按话筒说「38 块」/ 键盘输入 → 发送(带 draftId) → created（续写，现有逻辑）
  │            └─ 超过 30 分钟草稿过期 → 提示重新描述
  ├─ 命中幂等 duplicate → 气泡「这条已经记过啦」+ [仍要再记]按钮(force=true)
  ├─ ignored(not_expense/query) → 不进确认卡，降级走现有流式对话/提示
  └─ 低置信度(ASR confidence < STT_LOW_CONFIDENCE 或 item.confidence 低)
        → 确认卡顶部黄条「识别可能不准确，请核对金额和分类」，金额/分类高亮可改（不阻断）
```

复用的现成前端分支：`tryBookkeeping` 已处理 created/clarify/duplicate/ignored 与 draftId 续写，语音只需在 `inputText` 回填后**走同一条 `handleSend` 路径**，再叠加 dry-run 确认卡与 overrides。

### 4.5 持久化与现有记账逻辑的衔接（E 层）

- `records` 表**零变更**：音频解析出的记录与手打/AI 文本记账完全同构（Decimal 金额、类型映射、软删 status）；
- `ai_bookkeeping_logs` 增加 **`source` 列（`VARCHAR(10) NOT NULL DEFAULT 'text'`，注释 `text/voice`）**：
  - `models/bookkeeping.py` 加 `source` 字段；
  - `sql/init_mysql.sql`、`sql/create_tables_from_models.sql` 同步；
  - 存量库执行：`ALTER TABLE ai_bookkeeping_logs ADD COLUMN source VARCHAR(10) NOT NULL DEFAULT 'text' COMMENT 'text/voice' AFTER user_id;`（迁移手册 08 已有流程）；
  - **备选（不想动表结构）**：退化为在 `parse_json` 内写 `{"source": "voice"}`，代价是审计查询不便；
- `raw_text` 存转写文本（≤500 字已有上限，ASR 文本天然符合）；
- 幂等不因语音形态改变：前端 voice 流程同样生成 `clientMsgId`；同一次录音重复提交 → duplicate 不重复入账；
- 纠错审计延续：确认卡改字段的 `overrides` 写入日志 `parse_json`；后续「改成45块」「删掉」的口语纠错在确认入账后依然可用（现有 PATCH/DELETE）。

### 4.6 异常与低置信度处理清单

| 场景 | 处理 | 形态 |
|---|---|---|
| 未授权录音/权限被拒 | 引导去设置 | 弹窗 + toast |
| 录音超 60s | 自动停止并转写 | 正常 UI 提示 |
| 文件过大/类型不对 | 后端 400，前端提示 | `ai_error` |
| 转写失败/服务不可用 | 后端 500 兜底日志；前端「识别暂不可用」+ [重试][改为键盘输入] | toast + 按钮降级 |
| 转写文本为空 | 「没听清，请再说一次」 | toast，不发送 |
| 识别低置信度 | 确认卡黄条强提示、字段高亮可改 | 不阻断 |
| 解析缺金额 | clarify 追问 + draftId 续写（文本/再录音均可） | 气泡 |
| 非记账内容 | ignored 降级对话/提示，不入账 | 气泡 |
| 重复提交 | duplicate + [仍要再记]（force） | 气泡 |
| 限流 | 每用户每分钟 N 次 | toast「说话太频繁」 |
| 未登录 | 现有全局 401 拦截 | 登录页 |

## 8. 验收标准

1. **E2E 主链路**：AI 助手页按住说话 → 文本回填可编辑 → 发送 → 确认卡 → 确认 → 气泡 echo + 「账单」列表出现该记录（金额/分类/日期正确）；
2. **字段映射正确率**（固定 30 条中文语音语料，含「元5」等口语金额、相对日期、收入、多笔）：金额全对且**零猜测性错误**（无金额必须 clarify）；分类命中 ≥ 24/30；相对日期推算正确；
3. **确认卡纠错**：修改金额/分类/日期后提交，落库值 = 修改值，日志 `parse_json` 含 overrides；
4. **clarify 续写**：说「打车」→ 追问金额 → 再录音说「38块」→ 入账，且只记一笔；
5. **幂等**：同一段录音的转写文本重复提交两次 → 第二次 duplicate，`records` 仅 1 条；
6. **隐私**：转写接口调用后临时目录无残留音频文件；
7. **可替换**：`STT_PROVIDER=openai_whisper` ↔ 假 provider（测试 mock）零代码切换，前端不受影响；
8. **安全/限流**：未登录 401；大小 >5MB、非白名单类型被拒；每分钟第 6 次转写被限流；异常不回显底层报错；
9. **回归**：`fast_backend` 现有 pytest 全绿；手打文本记账、Web 端记账行为不变。

5. **M5 验证收尾**：pytest 全量、H5 E2E 手测清单、`.env.example`/API 文档同步、CHANGELOG。

## 10. 风险与说明

- **两次 LLM 调用**（dry-run 预览 + 确认 create）：每笔语音记账比文本多一次解析。可接受（MVP）；优化项：按 `requestId` 缓存 5 分钟解析结果重复利用。
- **Whisper 对中文数字/单位（块、元5）的口语识别率**：转写文本常为「58块5」之类，normalizers 已覆盖「块/元+尾数」；低置信度提示兜底。
- **H5 录音兼容性**依赖浏览器 MediaRecorder；App/微信端权限配置必须占位（manifest 已列），否则打包后无法录音。
- **表结构变更影响存量部署**：若不想跑 ALTER，采用 4.5 备选方案（parse_json 记 source），验收标准 4.5 相应降级为「可通过 parse_json 区分来源」。
