## 设计背景

随着移动支付的普及，个人消费高度碎片化，依靠回忆或事后补录完成记账的难度显著上升，个人财务管理软件因此成为稳定的应用需求[1-2]。然而现有记账类产品的功能边界长期停留在"记录—分类—统计"这条主线上，能回答"这个月花了多少"，却无法回答"这样的消费结构是否健康"，此类问题需结合用户历史数据归纳推断，传统规则引擎难以覆盖。大语言模型（Large Language Model，LLM）为此提供了新的技术路径，可将交互方式从"填表单"转变为"直接提问"[3-4]，但落入真实系统面临三类工程困难：一是原型系统由 Spring Boot 网关、Express AI 服务与 sql.js 内存库三个异构进程构成，数据无法统一查询；二是任一环节的同步阻塞都会在单进程模型下随并发上升耗尽工作线程；三是模型输出偏离预定义结构的可靠性问题[18]。本课题即设计一款基于 FastAPI 与大语言模型的个人智能记账管理系统，将三进程原型重构为单个全异步进程，在保留传统记账能力的基础上实现智能问答、消费分析、预算规划与 FAQ 知识库检索，并保证外部服务不可用时系统仍能降级运行，对推动 LLM 应用工具在个人财务场景的工程化落地具有积极作用。

## 文献调研

近年来基于智能记账与个人财务助手的研究逐步增多，相关工作围绕个人财务管理软件、大模型金融应用与检索增强生成三条主线展开，技术形态从规则化统计聚合演进为模型驱动的语义理解与生成，应用场景从记账录入扩展到消费解读、预算规划与知识问答：

一、国内研究现状

1. 个人记账应用设计，潘沁园等面向大学生群体设计了智能消费记账 App[1]，刘露等实现了学生消费记账应用，相关工作在分类管理、图表统计与多账本支持上积累了完整经验，但产品普遍"重记录、轻解释"，数据解读责任完全交给用户。
2. 大模型金融应用与评估研究，陆岷峰系统梳理了大语言模型在金融端的应用原理、现实挑战与落地路径[5]，李毅等提出的 CFB 方法从任务覆盖广度与测评基准去污两方面改进了金融大模型的评估方案[6]，为个人理财场景的模型选型与效果衡量提供了参照。
3. 模型可靠性与幻觉抑制研究，刘泽垣等对大语言模型幻觉问题的成因与抑制手段进行了系统分析[7]，但现有研究以通用场景为主，缺少面向个人财务数据的针对性讨论。
4. 检索增强与问答技术，吴璇等对检索增强生成（Retrieval-Augmented Generation，RAG）的检索器优化与评估方法进行了综述[8]，文森等归纳了检索增强与提示工程两条技术路线在问答系统中的分工与适用边界[9]。
5. 系统安全与权限控制，申正阳等基于 JWT 实现了用户身份与服务权限认证[10]，范大娟等提出面向隐私保护的自适应访问控制方法[11]，可为多租户记账系统的数据隔离提供借鉴。

二、国外研究现状

1. 产品形态验证更早，以 Mint 为代表的平台通过聚合账户流水自动生成消费分类与月度报表，验证了"自动归集＋分类可视化"的产品形态；以 YNAB 为代表的零基预算工具把记账从事后记录推进到事前约束。
2. 金融领域专用大模型发展迅速，Wu 等人提出的 BloombergGPT 验证了领域语料对金融任务的提升作用[12]，Yang 等人提出的 FinGPT 以低成本微调与开源协作降低使用门槛[13]，两者共同确立了领域适配能带来实质收益的判断。
3. 基础技术脉络清晰，预训练语言模型解决语义表示问题[3-4]，思维链提示改善复杂推理表现[14]，基于人类反馈的指令对齐提升输出可控性[15]，为轻量化的场景适配提供了基础。
4. 检索增强生成成为主流框架，Lewis 等人提出 RAG 以缓解知识过期与事实幻觉[16]，Karpukhin 等人的稠密段落检索以双塔向量相似度完成召回[17]，确立"向量化—相似度检索—上下文注入"范式，但对服务降级条件下的系统可用性讨论薄弱。
5. 结构化输出与个性化适配受到关注，Wang 等提出的 SLOT 以模式引导解码缓解 schema 偏离[18]，但校验失败后从模型输出到落库呈现的衔接仍缺工程化讨论；Theerthala 的行为锚定推理链训练则提示，个人财务任务真正缺的是贴合用户自身的上下文而非更大的模型[19]。

综上，国内外研究为本课题提供了成熟的模块组合与可落实的方法路径，但存在三处不足：个人财务管理软件偏重功能实现而对架构整合讨论较少；大模型应用尚未弥合"模型能生成"与"程序能用"之间的工程断层；RAG 研究对故障降级条件下的可用性设计关注不足。本课题相应以个人记账系统为载体，研究异构架构整合、结构化输出的约束校验与降级、以及可降级的检索增强设计。

## 主要设计目的

本课题旨在设计并实现一套面向个人用户的智能记账管理系统，以单个 FastAPI 全异步进程为后端，通过多源数据协同与模块化设计，实现账单管理、统计分析、自然语言记账、流式智能问答、消费分析与预算规划及 FAQ 知识库检索等功能，构建一个集记录、理解与解读于一体的个人财务助手平台。

设计的主要目的体现在以下几个方面：一是降低持续记账负担，通过自然语言记账（如"早餐花了 15 元"即完成录入）与幂等去重、澄清追问机制，把记账由"事后补录"变为"对话式记录"，并消除并发重试导致的重复入账；二是提升数据解释能力，通过在对话中自动注入当月收支、环比与分类构成等真实财务上下文，使系统从"记录—分类—统计"升级为能回答消费结构是否健康的解读工具；三是验证工程方法并完成架构收敛，在不改动既有客户端接口契约的前提下，把"网关进程＋AI 服务进程＋内存库"的三进程异构结构重构为单个全异步服务，检验大模型结构化输出"约束—校验—降级"链路在真实系统中的有效性。

总体而言，本设计不仅能够验证大语言模型在个人财务场景中的应用效果，沉淀面向该场景的 LLM 接入范式，还能为多端一致的个人工具类系统架构整合提供可复用的工程样例，具有良好的实用推广与教学参考价值。

## 设计内容

本设计以 FastAPI 异步后端为核心，综合运用大语言模型调用、检索增强生成与多端前端技术，构建一套可实现账单管理、统计分析、自然语言记账、智能问答、消费分析与预算规划的记账管理系统。通过 Web 端、移动端与后端服务的协同开发，实现记账的智能化与人机交互的对话化，提升系统的智能化水平与应用价值。

系统总体设计：系统基于前后端分离与分层架构思想，由客户端层、服务端层与数据层三部分组成。客户端层包括 Web 管理端（用户端 8 页＋管理后台 4 页）与跨端移动端（10 个页面，一套代码覆盖 H5、微信小程序与 App）；服务端层为单个 FastAPI 全异步进程，按资源划分用户、分类、账单、统计、管理后台与 AI 助手六组路由，对外提供 46 个 REST 接口与 SSE 流式接口；数据层采用 MySQL 单库设计，共 9 张数据表，统一 InnoDB 引擎与 utf8mb4 字符集。系统整体通过统一鉴权与接口契约协调运行，实现信息采集、数据处理、模型生成与结果呈现的闭环结构。系统总体设计图如图 1 所示【待补充：需绘制】。

后端服务设计：主控制器采用 FastAPI + uvicorn，数据访问层采用 SQLAlchemy 2.0 异步引擎与 aiomysql 驱动，保证 SSE 长连接与常规并发请求互不阻塞；认证采用 PyJWT（HS256）无状态鉴权，口令以 bcrypt 哈希存储，管理端在认证依赖之上叠加角色校验；金额字段统一采用 DECIMAL(10,2) 定点类型并在 Pydantic 模型层以 Decimal 声明，从数据库与类型系统两侧杜绝浮点误差；统计查询采用左闭右开的可索引日期区间条件命中复合索引；配置集中于 .env，接口自动生成 OpenAPI 文档。

AI 能力设计：以 LangChain 通过 OpenAI 兼容接口接入对话、分析与 Embedding 三类模型，对话模型温度 0.7 开启流式输出，分析模型温度 0 并绑定 with_structured_output 进行 Pydantic 校验，校验失败即返回错误响应而不写入数据库；AI 流式对话在上下文组装环节自动注入用户真实账单的汇总数据，历史消息按近似 token 预算设置滑动窗口上限；自然语言记账通过幂等日志表的唯一键与归一化文本哈希实现 300 秒窗口去重，解析结果区分 created／clarify／ignored／duplicate 四种返回形态，缺金额时以草稿暂存、补充后续写完成入账；FAQ 检索以向量语义检索为主路径、关键词检索为降级路径，保证向量服务不可用时问答链路仍返回结果；预算规划将 50/30/20 分配法则与用户历史消费结构结合生成数据驱动的方案。

系统测试与优化：设计完成后，将从功能回归、结构化输出可靠性、降级可用性、幂等正确性与上下文组装质量五个方面进行验证。常规回归以 pytest 测试集覆盖安全工具函数、记账文本归一化与应用健康检查；专项验证包括畸形注入实验（非法输出落库数须为零）、Embedding 故障注入实验（降级态非空返回率须为 100%）、并发重放实验（重复请求仅产生一条记录）与"带财务上下文／仅系统提示"两条件的对照盲评实验。通过数据分析与调试，对校验规则、降级阈值与上下文预算进行优化，确保系统在大模型服务不稳定条件下依旧可用。

## 拟采取的设计方法

1. 文献调研：通过查阅个人财务管理、大模型金融应用与检索增强生成方向的国内外研究资料，了解智能记账系统的架构形态与 LLM 接入方案的现状趋势，为本设计提供理论依据与技术参考。
2. 需求分析与契约冻结：明确 Web 端 12 页、移动端 10 页的功能清单与 46 个接口规范，在客户端零改动约束下冻结接口路径、字段命名（camelCase）与双响应契约，作为后端重构的验收基线。
3. 系统设计：以分层架构（路由—CRUD—模型）思想构建系统总体架构，完成单库 9 表数据库设计、复合索引规划与鉴权依赖设计，确定异步驱动、幂等日志表与检索降级路径的实现方案。
4. 编码实现与联调：后端基于 FastAPI + SQLAlchemy 2.0 异步栈实现六组路由与 AI 模块，前端沿用 React 18 + Ant Design 5 与 uni-app（Vue 3）体系；以 Git 进行版本管理，配置 GitHub Actions 三条流水线（后端测试、Web 构建、移动端构建），以 Docker Compose 编排 MySQL、后端与 Web 端实现一键部署。
5. 系统测试与评估：在 pytest 回归基线上开展畸形注入、故障注入、并发重放与对照盲评四组专项实验，逐项核验验收口径并如实报告降级代价；根据测试数据修复缺陷、优化参数，最终整理实验结果完成毕业论文撰写与答辩。
