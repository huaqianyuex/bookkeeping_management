### WP-1 配置与启动 fail-closed（M2/M3/M4，09-26 ~ 09-29，2 投入日）

- **问题描述**：`config/settings.py:78` 用 `os.environ.setdefault` 修复不了 import 时已绑定的 `JWT_SECRET`——逃生门路径下实际以空串/源码固定串签名，读源码者可伪造 token；`config/db_config.py:21` 缺 `DATABASE_URL` 时回退源码内 `root:123456`；`:27` 恒开 `echo=True` 把含金额/手机号的 SQL 参数写入日志；`main.py` 无 lifespan、无 readiness。
- **修复目标**：生产缺关键配置即拒绝启动；SQL 参数不进日志；应用生命周期可测试。
- **实现方式**（文件级方案 §1–§3）：

  4. **先写失败测试** `tests/test_config_startup.py`（子进程方式启动断言退出/异常），再改代码。
- **所需资源**：`requirements-dev.txt` 首批依赖（pytest、pytest-asyncio、httpx）。
- **时间节点**：09-26 ~ 09-29。
- **验证标准**：

### WP-2 登录/注册防护（H1、L2、L3、L9 单机部分，09-30 ~ 10-08，5 投入日）

- **问题描述**：`schemas/users.py:13` 强制 6 位纯数字（空间 10^6）；`routers/user.py` 限流键为 `IP|username`，换代理 IP 即绕过；注册无限流、显式返回"用户名已存在"构成枚举 oracle、check-then-create 有竞态；`utils/throttle.py` 的 `is_locked()` 与 `record_fail()` 非原子，并发可穿透进 bcrypt；未知用户登录跳过 bcrypt 造成时序差异。
- **修复目标**：跨 IP 爆破与单 IP 喷洒均受限；并发不能穿透限流；新注册拒绝弱口令；存量用户登录不受影响并获得迁移引导。
- **实现方式**（文件级方案 §4–§5、§9–§10、§40）：
  1. `utils/throttle.py` 重构为 `LoginGuard` 接口 + 内存实现（明确仅单进程）：
     - 双桶：`acct:{canonical}`（5 次失败/15 分钟，锁 15 分钟）与 `ip:{trusted_ip}`（阈值放宽，建议 30 次/15 分钟，防 NAT 误伤）；
     - **原子预留原语**：模块级 `asyncio.Lock`（不要用 `threading.Lock` 阻塞事件循环）。`check_and_reserve()` 在锁内完成"读计数 → 判阈值 → 预写失败名额"，bcrypt 在锁外执行；`confirm_success()` 回滚名额并清桶，`confirm_failure()` 保留名额。这样 N 个并发错误登录最多 5 个进入 bcrypt；
     - 键长度上限、最大键数与惰性 GC，防字典膨胀。
  2. 新增 `utils/client_ip.py`：默认取 socket peer；`TRUSTED_PROXY_CIDRS` 非空时才解析 XFF 最后一跳。默认为空（无反代）。
  3. `schemas/users.py`：
     - `canonical_username()` = `strip()` + `casefold()`；
     - **collation 对齐（易埋坑，先验证再定规则）**：先在测试库执行 `SELECT 'Abc' = 'abc' COLLATE <实际列collation>;` 确认大小写语义；MySQL 8 默认 `utf8mb4_0900_ai_ci` 为 NO PAD、大小写不敏感，`casefold + strip` 与之兼容；若列是 PAD SPACE collation 需注意尾空格差异；
     - `validate_password_policy()`：12–128 位、拒绝纯数字与内置常见口令黑名单，不强制符号组合；
     - **登录口令不做强度校验**（仅限长 128），存量 PIN 可登录。
  4. `routers/user.py`：register 先 IP 限流 → 直接 insert，捕获 `IntegrityError` → 与参数校验失败统一为同一外部文案（L2/L3）；login 走 guard → 未知用户执行 `verify_dummy_password()`（启动时对随机串求一次 bcrypt，常数开销）→ 成功后按 `password_policy_version` 返回 `password_migration_required`；
  5. **存量 PIN 识别（v2.0 未解决的问题）**：服务端只有哈希，无法判断旧口令是否 6 位。在迁移 0002（WP-5 一并执行，或本 WP 提前执行同一迁移文件）加列 `password_policy_version TINYINT NOT NULL DEFAULT 0`；新注册写 1；登录响应按该字段返回 `password_migration_required`，前端展示引导文案。强制跳转改密页放 P1。
  6. 前端 P0 最小适配：Web 与 uniapp 的注册/改密表单更新校验规则与提示；登录表单不动。
- **所需资源**：无新三方依赖；前端两仓各一次小改版。
- **时间节点**：09-30 ~ 10-08。
- **验证标准**：
  - `pytest tests/test_user_throttle.py -q` 全绿；
  - 并发断言：`asyncio.gather` 100 个同账号错误登录，bcrypt `verify` 调用计数 ≤ 阈值（monkeypatch 计数）；

### WP-3 AI Guard（H2 + M7 P0 部分，10-06 ~ 10-11，3 投入日）

### WP-5 JWT 生命周期（M1，10-13 ~ 10-18，3 投入日）

- **问题描述**：改密/禁用不使旧 token 失效（24 小时窗口内泄露 token 持续可用）；解码不强制 `exp/sub`；非法 `sub` 可能 500；`Bearer` 解析不严格（纯 token 也能过）；`utils/auth.py` 三套认证逻辑重复。
- **修复目标**：改密后旧 token 立即 401；认证失败统一 401，不出现 500/422 分裂；引入版本化迁移框架。
- **实现方式**（文件级方案 §7–§8、§11、迁移 0001/0002）：
  1. **Alembic 接入存量库（具体步骤）**：`alembic init migrations` → `env.py` 挂 `models` 的 metadata 并显式导入全部模型 → 0001 baseline 迁移对空库 `upgrade head` 建全量 schema，对现有库执行 `alembic stamp head`（不重建）→ 0002 加 `users.token_version INT NOT NULL DEFAULT 0`、`users.password_policy_version TINYINT NOT NULL DEFAULT 0`（若 WP-2 未提前加）、`(role,status,id)` 复合索引。
  2. `utils/security.py`：payload 增加 `iat`、`tv`、`typ="access"`；decode 固定 `algorithms=["HS256"]`、`require=["sub","exp"]`。
  3. `utils/auth.py`：抽 `_resolve_token()` 统一：scheme 必须为 `Bearer ` 前缀 → decode → `int(sub)` 捕获异常 → 查用户存在与状态 → 比较 `tv` 与 DB `token_version`；所有失败抛 401；optional 变体捕获 401 返回 None。
  4. `crud/user.py::update_password()`：单条 UPDATE 同事务写新哈希与 `token_version = token_version + 1`；改密成功响应签发新 token。
  5. 管理员禁用用户：同一事务 bump `token_version`（与 WP-9b 的 actor 保护同一处改动，先做 bump）。
- **所需资源**：`alembic`（新依赖）；测试库。
- **时间节点**：10-13 ~ 10-18。
- **验证标准**：
  - `pytest tests/test_auth_token.py -q`：改密 → 旧 token 401、新 token 200；无 header/错误 scheme/纯 token/非法 sub/过期/伪造/版本不匹配全部 401 且响应体一致；
  - `alembic upgrade head` 在空库与现有库均可执行；`alembic downgrade -1 && alembic upgrade head` 可往返；重复执行幂等。

### WP-6 AI 记账强幂等（M6，10-19 ~ 10-27，5 投入日，P1 最难项）

- **问题描述**：`routers/ai.py` bookkeeping 先查 `dedup_hash` 再写（TOCTOU），并发同文且不带相同 `client_msg_id` 的请求各写一遍 records；占位日志失败后可能永久"处理中"无恢复路径。
- **修复目标**：相同 `(user_id, client_msg_id)` 只调一次 LLM、只写一组 records；同 key 不同请求体返回 409；LLM 失败或进程崩溃后可恢复，不留永久 processing。
- **实现方式**（文件级方案 §12.7、§21.6–7、§45、§49、迁移 0004）：
  1. 新增 `models/ai_idempotency.py`：`user_id/scope/client_msg_id/request_hash/state/owner_token/lease_expires_at/response_json/record_ids/error_code`，唯一键 `(user_id, scope, client_msg_id)`；状态机 `reserved → processing → succeeded/failed`。**不对金额或 `dedup_hash` 建唯一约束**（保留"买两杯同价咖啡"的合法重放）。
  2. 关键顺序：① 短事务 `INSERT ... state=reserved`（唯一键仲裁并发，捕获 IntegrityError 后改为读既有记录）→ ② 同事务置 `processing` + `lease_expires_at` 并 commit → ③ **无事务持有**调 LLM → ④ 短事务写 records + audit + `succeeded` + `record_ids`。任何一步失败置 `failed`，lease 过期后新请求可原子接管（`UPDATE ... SET state='processing' WHERE state='processing' AND lease_expires_at < NOW()`，影响行数=1 者接管）。
  3. `request_hash = sha256(规范化请求体)`；同 key 同 hash 且 `succeeded` → 直接返回原结果；同 key 不同 hash → 409。
  4. `schemas/ai.py`：`BookkeepingIn` 加 model_validator，`dry_run=false` 必须带合法 UUID `client_msg_id`；旧客户端兼容期用开关 `REQUIRE_CLIENT_MSG_ID`（默认先关：缺失时服务端生成一次性 ID + 告警日志；前端改造完成后置开并观察一周）。
  5. 并发验证必须用真实 MySQL（SQLite 不支持行级并发语义）。
  - **降级预案**：若 10-27 未完成 stale lease 接管，先交付"强制 clientMsgId + 唯一键 + succeeded 重放"，接管逻辑移入 WP-9 批次。
- **所需资源**：本地测试 MySQL 库；alembic 0004。
- **时间节点**：10-19 ~ 10-27。
- **验证标准**（`pytest tests/test_bookkeeping_idempotency.py -q`，真实 MySQL）：
  - 20 个并发相同 `clientMsgId` → LLM 调用计数 = 1，records 一组；
  - 同 key 不同请求体 → 409，无新写入；
  - 注入 LLM 异常 → 状态 `failed`，lease 到期后重试成功，无永久 processing；
  - `succeeded` 重试返回原结果（不再计费）。

### WP-7 会话/消息资源治理（M7 完整，10-28 ~ 11-01，2.5 投入日）

## 6. 止损与回滚（单人版）

- **发布顺序**：先测试库 → 本地起服务全量回归 → 再部署到实际环境；数据库变更前先 `mysqldump`。
- **分支与提交**：`security-hardening` 分支上每 WP ≥1 commit；回滚用 `git revert`，不做覆盖式 checkout。
- **配置开关**（settings 布尔项）：`REQUIRE_CLIENT_MSG_ID`、AI 配额启用/熔断、FAQ 预热、scheduler 开关。出问题先关开关再查代码。
- **数据库回滚**：优先"旧代码兼容新 schema"（新列可空/有默认值），故障时先回代码，不删列不删索引。
- **密钥疑似泄露**：轮换 `JWT_SECRET` + 全员 `token_version` bump + 强制重新登录，不做旧 token 宽限。
- **检查清单**（每次出口检查过一遍）：worker=1？`.env` 三项在位？备份是新的？日志无 SQL 参数/聊天原文？供应商预算告警在位？
